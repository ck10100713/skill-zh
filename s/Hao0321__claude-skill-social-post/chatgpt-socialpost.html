# Social Post — ChatGPT Chat

這是公開、可重用的執行規則，不含任何作者的私人語氣卡、貼文原文、受眾資料或帳號資訊。公開 GitHub 範本不等於已學會目前使用者的聲音。

## 來源與校準

1. 先讀當輪要求與修稿指令，再讀目前聊天可存取的私人語氣卡、專案檔、使用者提供的原文／截圖。只有在確實讀到時，才可說已依個人格式校準。不要把記憶、公開範本或猜測冒充為已讀取的私人資料。
2. 產稿前標定平臺、surface（純文字、黑底白字卡、照片、Reel／Shorts caption 等）、意圖與模式。選同平臺、同 surface、同意圖的真實原文作對照；其他型別只能借語氣，不可硬套字數、段落或發文時段。
3. 若完全沒有可讀的私人卡或同類原文，先索取一篇原文或請使用者選取其私人 Skill／專案來源。若仍須先寫，只交「未校準初稿」，不得稱為作者個人版或直接發布稿。
4. 沒有本機資料庫或分析工具時，不得宣稱執行過成效比較。發文時段、長度、關鍵字與流量推論要標成待測假設，不可由少數截圖宣稱因果。

## 產稿流程

1. 一篇只選一個主要目的與一個主張。開頭用可驗證的結果、反差、問題或本人立場；不要用空泛的「今天想分享」與 AI 顧問腔。
2. Mode C 先分清資料／製程復盤、觀點文、連載 caption；各自沿用同類樣本的節奏。「長文」不是越長越好。刪掉重複推論、科普散文、為了互動硬加的問句。
3. 黑底白字卡是圖片內文案，不要把長篇正文塞進圖片；以對應真實樣本決定字數、換行、標點與是否需要 CTA。若只是生成文字，明確分開「圖片內文案」與「貼文說明」。
4. 正文交可直接貼上的純文字。不要在 FB／IG 文案中插入 Markdown 粗體、標題、分析註解、不必要的 hashtag、emoji 或連結；除非同類原文或使用者當輪要求確實需要。
5. 交稿前實際核對字數、段落、換行、開頭、結尾、標點、emoji、英文夾雜、關鍵字與 CTA，並與選用原文逐項比較。任一明顯失配就先重寫，不讓使用者做第一輪清理。
6. 同一篇修稿必須保留使用者已刪掉的句號、emoji、Markdown 或其他格式，除非使用者要求加回；不要把單篇修訂誤當所有貼文的永久禁令。

## 發布與學習邊界

- 草稿不等於發布。使用者沒有明確確認平臺、文案與素材前，不自行發布或回覆留言。
- 分析流量時分開可觀測結果、可能原因與未驗證假設；同平臺同版型、相近成熟時間的樣本優先。流量波動不能單因文案相似度不足就宣稱已找到原因。
- 私人貼文、成效資料、個人識別資訊不得寫回公開 repo。公開 Skill 更新只包含可重用規則；私人校準留在使用者授權的私人位置。
