# Deploy — IaC Execution & Health Verification

## Quick Reference

| Property | Value |
|----------|-------|
| Best for | 對 Azure 執行已驗證的 IaC，並對部署好的資源做健康檢查 |
| Inputs | `.copilot-azure/sessions/{id}/` 裡的 `prepare-plan.json` + `scaffold-manifest.json` |
| Outputs | 寫到 session 目錄的 `deploy-result.json` |
| Parent | [azure-app-onboard](../SKILL.md) |

## When to Use This Skill

當 `scaffold-manifest.json` 存在、而且有 `files[]` 和 `validationResult` 時，由 `azure-app-onboard` orchestrator 在 Phase 4 呼叫。使用者不能直接觸發。

> **回到 orchestrator：** 完成後，把控制權交還給 `azure-app-onboard` 做 handoff（Step 10）。不要開始新的 phase。

## When NOT to Use

| Scenario | Use Instead |
|----------|-------------|
| 規劃架構、對應服務、估算成本 | [prepare](../prepare/SKILL.md) |
| 從 plan 產生 IaC 檔案 | `azure-app-onboard` Step 7 (scaffold) |
| 執行 `azd up` 或既有的部署範本 | `azure-deploy` |
| 部署後除錯正在跑的 app | `azure-diagnostics` |
| 最佳化現有的 Azure 支出 | 選用的 `azure-cost` plugin 裡的 `cost-optimization` |

如果 `cost-optimization` 不能用，要說明它是由選用的 `azure-cost` plugin 提供，
並引導使用者走他們的 client 所支援的 plugin 安裝流程；不要暗示 handoff 已經完成。

## Workflow

> ⛔ **Step 0 一定要委派給 sub-agent。** 讀 `subagent-preflight.md`，然後把 `<<<TEMPLATE_START>>>` / `<<<TEMPLATE_END>>>` 分隔符號之間**完整且未修改**的範本文字，當成 `task` 派出去。不准摘要或改寫範本，sub-agent 需要每一條「Read [file]」的指示，才能產生正確的 `deploy-checklist.md`。Session artifact 的資料要附在範本區塊**後面**。如果你讀完範本之後的下一個動作不是 `task`，就代表你是在 inline 自己執行，而不是委派。

> ⛔ **Healing loop：** 嘗試 3 次後問使用者，之後每 5 次問一次（計數 = `healingAttempts[].length`）。

> ⛔ **Region lock：** 重試 `az deployment` 之前，把 `--location` 和 `prepare-plan.json.deploymentVariables.location` 比對。如果變了 → 需要重新核准的 gate。核准後更新 plan。

> ⛔ **compaction 之後，或任何 `az deployment`/`az webapp deploy`/`az acr build`/health check 失敗之後：重新讀 `deploy-checklist.md`。** 如果檔案不見了 → 從 [`deploy-checklist-template.md`](references/deploy-checklist-template.md) 填一份。如果 context 大量遺失：也要重新讀這份 SKILL.md。

## Quick Reference

| Property | Value |
|----------|-------|
| Best for | Executing validated IaC against Azure, health-checking deployed resources |
| Inputs | `prepare-plan.json` + `scaffold-manifest.json` from `.copilot-azure/sessions/{id}/` |

## When to Use This Skill

Invoked by the `azure-app-onboard` orchestrator at Phase 4 when `scaffold-manifest.json` exists with `files[]` and `validationResult`. Not directly user-routable.

> **Return to orchestrator:** When complete, return control to `azure-app-onboard` for handoff (Step 10). Do NOT start new phases.

## When NOT to Use

| Scenario | Use Instead |
|----------|-------------|
| Plan architecture, map services, estimate costs | [prepare](../prepare/SKILL.md) |
| Generate IaC files from a plan | `azure-app-onboard` Step 7 (scaffold) |
| Run `azd up` or execute existing deployment templates | `azure-deploy` |
| Debug a running app after deployment | `azure-diagnostics` |
| Optimize existing Azure spending | `cost-optimization` from the optional `azure-cost` plugin |

If `cost-optimization` is unavailable, explain that it is provided by the
optional `azure-cost` plugin and direct the user to their client's supported
plugin installation flow; do not imply the handoff completed.

## Workflow

> ⛔ **Sub-agent delegation is MANDATORY for Step 0.** Read `subagent-preflight.md`, then dispatch as a `task` with the **COMPLETE and UNMODIFIED** template text between `<<<TEMPLATE_START>>>` / `<<<TEMPLATE_END>>>` delimiters. If your next action after reading the template is anything other than `task`, you are executing it inline instead of delegating.

> ⛔ **Healing loop:** ask user after 3 attempts, then every 5 (counter = `healingAttempts[].length`).

> ⛔ **Region lock:** Before `az deployment` retry, compare `--location` against `prepare-plan.json.deploymentVariables.location`. If changed → re-approval gate required. Update plan after approval.

> ⛔ **After compaction or any `az deployment`/`az webapp deploy`/`az acr build`/failed health check: re-read `deploy-checklist.md`.** If missing → fill from [`deploy-checklist-template.md`](references/deploy-checklist-template.md). On significant context loss: also re-read this SKILL.md.
