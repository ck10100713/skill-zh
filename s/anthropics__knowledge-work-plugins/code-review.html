# /code-review

> 如果看到不認識的 placeholder，或需要確認目前連了哪些工具，請看 [CONNECTORS.md](../../CONNECTORS.md)。

用結構化的角度審查程式碼變更，涵蓋安全性、效能、正確性和可維護性。

## 用法

```
/code-review <PR URL or file path>
```

審查提供的程式碼變更：@$1

如果沒有指定檔案或 URL，就問要審查什麼。

## 運作方式

```
┌─────────────────────────────────────────────────────────────────┐
│                      CODE REVIEW                                   │
├─────────────────────────────────────────────────────────────────┤
│  STANDALONE（永遠能用）                                          │
│  ✓ 貼 diff、PR URL，或指定檔案                                  │
│  ✓ 安全稽核（OWASP top 10、injection、auth）                    │
│  ✓ 效能審查（N+1、記憶體洩漏、複雜度）                          │
│  ✓ 正確性（邊界情況、錯誤處理、race condition）                 │
│  ✓ 風格（命名、結構、可讀性）                                   │
│  ✓ 附程式碼範例的可執行建議                                     │
├─────────────────────────────────────────────────────────────────┤
│  SUPERCHARGED（連上你的工具之後）                                │
│  + 版本控制：自動拉 PR diff                                      │
│  + 專案追蹤：把發現連到 ticket                                   │
│  + 知識庫：對照團隊的 coding standard 檢查                       │
└─────────────────────────────────────────────────────────────────┘
```

## 審查面向

### 安全性
- SQL injection、XSS、CSRF
- 認證與授權缺陷
- 程式碼裡的 secret 或憑證
- 不安全的反序列化
- Path traversal
- SSRF

### 效能
- N+1 query
- 不必要的記憶體配置
- 演算法複雜度（熱路徑裡的 O(n²)）
- 缺少資料庫 index
- 沒有上限的查詢或迴圈
- 資源洩漏

### 正確性
- 邊界情況（空輸入、null、overflow）
- Race condition 與並行問題
- 錯誤處理與傳遞
- Off-by-one 錯誤
- 型別安全

### 可維護性
- 命名清不清楚
- 單一職責
- 重複的程式碼
- 測試覆蓋率
- 不直觀的邏輯有沒有文件

# /code-review

> If you see unfamiliar placeholders or need to check which tools are connected, see [CONNECTORS.md](../../CONNECTORS.md).

Review code changes with a structured lens on security, performance, correctness, and maintainability.

## Usage

```
/code-review <PR URL or file path>
```

Review the provided code changes: @$1

If no specific file or URL is provided, ask what to review.

## How It Works

```
┌─────────────────────────────────────────────────────────────────┐
│                      CODE REVIEW                                   │
├─────────────────────────────────────────────────────────────────┤
│  STANDALONE (always works)                                       │
│  ✓ Paste a diff, PR URL, or point to files                      │
│  ✓ Security audit (OWASP top 10, injection, auth)               │
│  ✓ Performance review (N+1, memory leaks, complexity)           │
│  ✓ Correctness (edge cases, error handling, race conditions)    │
│  ✓ Style (naming, structure, readability)                        │
│  ✓ Actionable suggestions with code examples                    │
├─────────────────────────────────────────────────────────────────┤
│  SUPERCHARGED (when you connect your tools)                      │
│  + Source control: Pull PR diff automatically                    │
│  + Project tracker: Link findings to tickets                     │
│  + Knowledge base: Check against team coding standards           │
└─────────────────────────────────────────────────────────────────┘
```

## Review Dimensions

### Security
- SQL injection, XSS, CSRF
- Authentication and authorization flaws
- Secrets or credentials in code
- Insecure deserialization
- Path traversal
- SSRF

### Performance
- N+1 queries
- Unnecessary memory allocations
- Algorithmic complexity (O(n²) in hot paths)
- Missing database indexes
- Unbounded queries or loops
- Resource leaks

### Correctness
- Edge cases (empty input, null, overflow)
- Race conditions and concurrency issues
- Error handling and propagation
- Off-by-one errors
- Type safety

### Maintainability
- Naming clarity
- Single responsibility
- Duplication
- Test coverage
- Documentation for non-obvious logic
