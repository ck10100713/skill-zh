# 反向連結概況分析

## 來源偵測

分析之前，先偵測有哪些資料來源可用：

1. **DataForSEO MCP**（付費）：檢查 `backlinks_summary` 工具是否可用
2. **Moz API**（免費註冊）：`"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run backlinks_auth.py --check moz --json`
3. **Bing Webmaster**（免費註冊）：`"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run backlinks_auth.py --check bing --json`
4. **Keywords Everywhere**（免費註冊；網域排名加上參照網域數量）：`"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run backlinks_auth.py --check keywordseverywhere --json`
5. **Common Crawl**（一律可用）：帶有 PageRank 的網域層級圖
6. **驗證爬蟲**（一律可用）：檢查已知的反向連結是否還在

執行 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run backlinks_auth.py --check --json`，一次偵測所有來源。

如果除了一律可用的那一層之外，沒有設定任何來源：
- 仍然用 Common Crawl 的網域指標產生報告
- 建議：「執行 `/seo backlinks setup`，加入免費的 Moz 和 Bing API key，取得更豐富的資料」

## 快速參考

| 指令 | 用途 |
|---------|---------|
| `/seo backlinks <url>` | 完整的反向連結概況分析（使用所有可用的來源） |
| `/seo backlinks gap <url1> <url2>` | 競爭對手的反向連結缺口分析 |
| `/seo backlinks toxic <url>` | 有害連結偵測與 disavow 建議 |
| `/seo backlinks new <url>` | 新增與流失的反向連結（只有 DataForSEO） |
| `/seo backlinks verify <url> --links <file>` | 驗證已知的反向連結是否還在 |
| `/seo backlinks setup` | 顯示免費反向連結 API 的設定說明 |

## 分析框架

產出下面全部 7 個區塊。每個區塊都按偏好順序，列出資料來源。

### 1. 概況總覽

**DataForSEO：** `backlinks_summary` → 反向連結總數、參照網域、網域排名、follow 比例、趨勢。

**Moz API：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json` → Domain Authority、Page Authority、Spam Score、連結的 root domain、外部連結。

**Keywords Everywhere：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run keywordseverywhere_api.py rank <domain> --json` → 依照目前的 API，回傳 0-10 的 Open PageRank（`open_page_rank`）、一個全球的 `rank`，以及參照網域數量（`referring_domains`）；沒有錨點或個別連結。Moz 沒設定時當作備援；兩者都有時，不要用它取代 Moz。

**Common Crawl：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run commoncrawl_graph.py <domain> --json` → PageRank、harmonic centrality，以及低信心的排名/存在資料。

**評分：**

| 指標 | 良好 | 警告 | 嚴重 |
|--------|------|---------|----------|
| 參照網域 | >100 | 20-100 | <20 |
| Follow 比例 | >60% | 40-60% | <40% |
| 網域多樣性 | 沒有單一網域 >5% | 1 個網域 >10% | 1 個網域 >25% |
| 趨勢 | 成長或持平 | 緩慢下滑 | 快速下滑（每季 >20%） |

### 2. 錨點文字分布

**DataForSEO：** `backlinks_anchors`

**Moz API：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py anchors <url> --json`

**Bing Webmaster：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run bing_webmaster.py links <url> --json`（從連結細節中取出錨點文字）

**健康分布的 benchmark：**

| 錨點類型 | 目標範圍 | 過度優化的訊號 |
|-------------|-------------|-------------------------|
| 品牌（公司/網域名稱） | 30-50% | <15% |
| URL/裸連結 | 15-25% | N/A |
| 泛用（「click here」、「learn more」） | 10-20% | N/A |
| 完全符合的關鍵字 | 3-10% | >15% |
| 部分符合的關鍵字 | 5-15% | >25% |
| 長尾 / 自然 | 5-15% | N/A |

如果完全符合的錨點超過 15%，要標記出來，當作需要審視的 heuristic；這可能代表不自然或連結垃圾的模式。

### 3. 參照網域品質

**DataForSEO：** `backlinks_referring_domains`

**Moz API：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py domains <url> --json` → 附帶 DA 分數的網域

**Common Crawl：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run commoncrawl_graph.py <domain> --json` → 網域層級的排名/存在資料，沒有經過驗證的參照網域數量

分析：
- **TLD 分布**：.edu、.gov、.org = 高權威。過多的 .xyz、.info = 低品質
- **國家分布**：要符合目標市場。80% 以上來自不相關的國家 = PBN 訊號
- **網域排名分布**：健康的概況，各個權威層級都有連結
- **每個網域的 follow/nofollow**：只給 nofollow 的網站 = SEO 價值有限

### 4. 有害連結偵測

**DataForSEO：** `backlinks_bulk_spam_score` + 參考資料裡的有害模式

**Moz API：** 從 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json` 取得廠商原始的 spam_score（要標註來源；只有對照目前的 Moz 文件驗證過之後，才套用門檻）

**驗證爬蟲：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run verify_backlinks.py --target <url> --links <file> --json`（驗證可疑的連結是否還存在）

**高風險指標（立刻標記）：**
- 來自已知 PBN（Private Blog Network）網域的連結
- 不自然的錨點文字模式（某個網域 100% 都是完全符合）
- 來自被處罰或被移出索引的網域的連結
- 大量目錄提交（50 個以上的目錄連結）
- 連結農場（每頁有 10K 以上外連的網站）
- 付費連結的模式（整個網域所有頁面的 footer/sidebar 連結）

**中風險指標（人工審視）：**
- 來自不相關領域的連結
- 互相連結的模式
- 來自薄內容頁面的連結（<100 字）
- 單一網域的連結過多（單一網域超過 50 條反向連結）

載入 `../seo/references/backlink-quality.md`，取得完整的 30 種有害模式和 disavow 準則。

### 5. 反向連結最多的頁面

**DataForSEO：** `backlinks_backlinks`，目標類型為 "page"

**Moz API：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py pages <domain> --json`

找出：
- 哪些頁面吸引了最多的反向連結
- 擁有高權威連結的頁面（連結磁鐵）
- 零反向連結的頁面（內部連結的機會）
- 有反向連結的 404 頁面（用 redirect 取回連結權益的機會）

### 6. 競爭對手缺口分析

**DataForSEO：** 兩個網域都用 `backlinks_referring_domains`，然後比較

**Bing Webmaster：** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run bing_webmaster.py compare <url1> <url2> --json`，只有在兩個 property 都已註冊，而且同一個 Bing API 帳號都能存取時才用。任意的競爭對手，用 DataForSEO、Moz 或 Common Crawl。

**Moz API：** 對每個網域各用一次 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json`，比較網域之間的 DA/PA

輸出：
- 連到競爭對手、但沒連到目標的網域 = 建立連結的機會
- 兩邊都連的網域 = 驗證現有的關係
- 只連到目標的網域 = 競爭優勢
- 前 20 名建立連結的機會，附上網域權威

### 7. 新增與流失的反向連結

**只有 DataForSEO：** `backlinks_backlinks`，加上日期篩選，看 30/60/90 天的變化

**驗證爬蟲：** 已知的連結，用 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run verify_backlinks.py --target <url> --links <file> --json` 驗證目前的狀態

**備註：** 免費的來源無法追蹤隨時間新增/流失的連結。如果沒有 DataForSEO 卻要求這個區塊，要告訴使用者：「連結成長速度的追蹤需要 DataForSEO 擴充功能。免費來源只提供某個時間點的快照。」

**警訊：**
- 新連結突然暴增（可能是負面 SEO 攻擊）
- 突然流失大量連結（網站被處罰或內容被移除）
- 連續 3 個月以上成長速度下滑（內容吸引不到連結）

## 反向連結健康分數

計算 0-100 的分數。混用多個來源時，要套用信心加權：

| 因素 | 權重 | 來源（偏好順序） | 信心 |
|--------|--------|---------------------------|------------|
| 參照網域數量 | 20% | DataForSEO > Moz | 1.0 / 0.85 |
| 網域品質分布 | 20% | DataForSEO > Moz DA 分布 | 1.0 / 0.85 |
| 錨點文字的自然度 | 15% | DataForSEO > Moz > Bing 錨點 | 1.0 / 0.85 / 0.70 |
| 有害連結比例 | 20% | DataForSEO > Moz spam score | 1.0 / 0.85 |
| 連結成長速度趨勢 | 10% | 只有 DataForSEO | 1.0 |
| Follow/nofollow 比例 | 5% | DataForSEO > Bing 細節 | 1.0 / 0.70 |
| 地理相關性 | 10% | DataForSEO > Bing 國家 | 1.0 / 0.70 |

**資料充足度關卡：** 算算 7 個因素之中，有幾個至少有一個資料來源可用。
- **有資料的因素達 4 個以上：** 產出 0-100 的數字分數（把缺少的權重按比例重新分配）
- **不到 4 個因素：** 絕對不要產出數字分數。改成顯示：
  ```
  Backlink Health Score: INSUFFICIENT DATA (X/7 factors scored)
  ```
  顯示有的個別因素分數，附上它們的來源和信心。
  建議：「設定 Moz API（免費），才能得到可以計分的概況。執行 `/seo backlinks setup`」

### 絕對不准：對沒量測過的東西打分數

**當 Common Crawl 是唯一可用的來源時，絕對不准產出任何形式的數字分數** -- 不管是健康分數、個別因素的分數，還是「大約」或「估計」的數字。Common Crawl 只提供排名和存在的訊號。要回報低信心的排名/存在資料，並且在每一個數字的位置，改寫成字面上的 `Not Assessed`。

**用 `source: not-assessed` 寫出來的 finding，絕對不准帶有數字分數。**

來源不到 4 個，卻給出數字分數，是**誤導**：它暗示健康度很差，但實際上只是我們缺資料。

### 驗證關卡（必要，不是選配）

這條規則以前在這個 skill 裡就寫過，但還是被違反，所以現在把它變成可檢查的。**在寫出任何反向連結的輸出之前，先執行驗證器：**

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run validate_backlink_report.py --report <report>.json --json
```

傳入你實際蒐集到的來源（`cc_data`、`moz_data`、`bing_data`、`dataforseo_data`、`scoring_factors` 和你的 `findings` 清單）。出現下列情況時，`source_score_consistency` 檢查會讓報告以 `status: FAIL` 失敗：

- 有數字分數，卻沒有任何可計分的來源（Moz、Bing 或 DataForSEO）提供資料 -- 也就是只有 Common Crawl 的情況，以及
- 任何標為 `source: not-assessed` 的 finding，帶有數字的 `score`、`value` 或 `health_score`。

**如果驗證器回傳 `status: FAIL`，就不要呈現這份報告。** 修正 findings -- 把有問題的數字換成 `Not Assessed` -- 然後重跑，直到通過為止。

## 錯誤處理

| 錯誤 | 原因 | 解法 |
|-------|-------|-----------|
| 沒有設定任何來源 | 沒有 API key，也沒有 DataForSEO | 執行 `/seo backlinks setup` |
| Moz 限流 | 免費方案：每 10 秒 1 次請求 | 等 10 秒再重試。script 已內建。 |
| Bing 網站未驗證 | 網站沒有在 Bing 驗證 | 到 https://www.bing.com/webmasters 驗證 |
| CC 下載逾時 | 圖檔很大，網路又慢 | 使用 `--timeout 180` 旗標 |
| DataForSEO 不可用 | 擴充功能沒安裝 | 執行 `./extensions/dataforseo/install.sh` |
| 沒有回傳反向連結資料 | 網域太新或非常小 | 備註：小網站的反向連結可能不到 10 條 |

**備援串接：**
1. DataForSEO 可用嗎？ → 作為主要來源（信心：1.0）
2. 有設定 Moz 嗎？ → 用於 DA/PA/spam/錨點（信心：0.85）
3. 有設定 Bing 嗎？ → 只有在兩個 property 都能存取時，才用於已註冊 property 的連結和比較（信心：0.70）
4. 沒設定 Moz，但有 Keywords Everywhere？ → 用於概況總覽中只有排名的備援（信心：0.60；單一指標，沒有連結數量/錨點）
5. 一律：Common Crawl 提供網域層級的指標（信心：0.50）
6. 一律：驗證爬蟲用於已知連結的檢查（信心：0.95）
7. 都不行？ → 「執行 `/seo backlinks setup` 設定免費的 API」

## 交付前審查（必做）

在把任何反向連結分析呈現給使用者之前，先在內部走過這份檢查清單。
不准跳過這一步。有發現問題，先修好再顯示報告。

### 每一項宣稱都要事實查核
- [ ] **Schema 的宣稱**：parse_html 有沒有為每個區塊回傳 `@type`？如果有任何 `@type` 缺少，重新檢查，它可能用了 `@graph` 外包（那是有效的 JSON-LD，不是格式錯誤）。
- [ ] **「link_removed」的 findings**：頁面是 JS 渲染的嗎？如果是 `unverifiable_js`，要這樣講，絕對不要把 JS 渲染的頁面回報成「連結被移除」（那是 false negative）。
- [ ] **H1 的 findings**：有沒有任何 H1 在 `h1_suspicious` 清單裡？如果有，註明它們很可能是計數器/統計數字，不是語意上的標題。
- [ ] **互相連結**：如果網站 A 連到網站 B，而 B 也連回 A，要標記為互相連結的模式。把外連和已驗證的內連來源對照檢查。
- [ ] **健康分數**：7 個因素有 4 個以上有計分嗎？如果沒有，回報 INSUFFICIENT DATA，絕對不要顯示誤導的數字分數。

### 驗證資料來源的標籤
- [ ] 報告裡每個指標都有來源標籤（例如「Parsed (0.95)」、「CC (0.50)」）
- [ ] 每個「找不到」的結果，都要區分「沒爬到」、「低於門檻」和「錯誤」
- [ ] 社群媒體頁面標為 `unverifiable_js`（不是 `link_removed`）

### 交叉檢查一致性
- [ ] 平台偵測要符合實際的訊號（檢查 wp-content、shopify CDN 等）

## Analysis Framework

Produce all 7 sections below. Each section lists data sources in preference order.

### 1. Profile Overview

**DataForSEO:** `backlinks_summary` → total backlinks, referring domains, domain rank, follow ratio, trend.

**Moz API:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json` → Domain Authority, Page Authority, Spam Score, linking root domains, external links.

**Keywords Everywhere:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run keywordseverywhere_api.py rank <domain> --json` → 0-10 Open PageRank (`open_page_rank`), a global `rank`, and a referring-domain count (`referring_domains`), per the current API; no anchors or individual links. Use as a fallback when Moz isn't configured; do not use in place of Moz when both are available.

**Common Crawl:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run commoncrawl_graph.py <domain> --json` → PageRank, harmonic centrality, and low-confidence rank/presence data.

**Scoring:**

| Metric | Good | Warning | Critical |
|--------|------|---------|----------|
| Referring domains | >100 | 20-100 | <20 |
| Follow ratio | >60% | 40-60% | <40% |
| Domain diversity | No single domain >5% | 1 domain >10% | 1 domain >25% |
| Trend | Growing or stable | Slow decline | Rapid decline (>20%/quarter) |

### 2. Anchor Text Distribution

**DataForSEO:** `backlinks_anchors`

**Moz API:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py anchors <url> --json`

**Bing Webmaster:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run bing_webmaster.py links <url> --json` (extract anchor text from link details)

**Healthy distribution benchmarks:**

| Anchor Type | Target Range | Over-Optimization Signal |
|-------------|-------------|-------------------------|
| Branded (company/domain name) | 30-50% | <15% |
| URL/naked link | 15-25% | N/A |
| Generic ("click here", "learn more") | 10-20% | N/A |
| Exact match keyword | 3-10% | >15% |
| Partial match keyword | 5-15% | >25% |
| Long-tail / natural | 5-15% | N/A |

Flag if exact-match anchors exceed 15% as a review heuristic; it may indicate unnatural or link-spam patterns.

### 3. Referring Domain Quality

**DataForSEO:** `backlinks_referring_domains`

**Moz API:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py domains <url> --json` → domains with DA scores

**Common Crawl:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run commoncrawl_graph.py <domain> --json` → domain-level rank/presence data, no verified referring-domain counts

Analyze:
- **TLD distribution**: .edu, .gov, .org = high authority. Excessive .xyz, .info = low quality
- **Country distribution**: Match target market. 80%+ from irrelevant countries = PBN signal
- **Domain rank distribution**: Healthy profiles have links from all authority tiers
- **Follow/nofollow per domain**: Sites that only nofollow = limited SEO value

### 4. Toxic Link Detection

**DataForSEO:** `backlinks_bulk_spam_score` + toxic patterns from reference

**Moz API:** Raw vendor spam_score from `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json` (source-label the value; apply thresholds only if verified against current Moz docs)

**Verification Crawler:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run verify_backlinks.py --target <url> --links <file> --json` (verify suspicious links still exist)

**High-risk indicators (flag immediately):**
- Links from known PBN (Private Blog Network) domains
- Unnatural anchor text patterns (100% exact match from a domain)
- Links from penalized or deindexed domains
- Mass directory submissions (50+ directory links)
- Link farms (sites with 10K+ outbound links per page)
- Paid link patterns (footer/sidebar links across all pages of a domain)

**Medium-risk indicators (review manually):**
- Links from unrelated niches
- Reciprocal link patterns
- Links from thin content pages (<100 words)
- Excessive links from a single domain (>50 backlinks from 1 domain)

Load `../seo/references/backlink-quality.md` for the full 30 toxic patterns and disavow criteria.

### 5. Top Pages by Backlinks

**DataForSEO:** `backlinks_backlinks` with target type "page"

**Moz API:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py pages <domain> --json`

Find:
- Which pages attract the most backlinks
- Pages with high-authority links (link magnets)
- Pages with zero backlinks (internal linking opportunities)
- 404 pages with backlinks (redirect opportunities to reclaim link equity)

### 6. Competitor Gap Analysis

**DataForSEO:** `backlinks_referring_domains` for both domains, then compare

**Bing Webmaster:** `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run bing_webmaster.py compare <url1> <url2> --json`
only when both properties are registered and accessible to the same Bing API
account. For arbitrary competitors, use DataForSEO, Moz, or Common Crawl.

**Moz API:** Compare DA/PA between domains via `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run moz_api.py metrics <url> --json` for each

Output:
- Domains linking to competitor but NOT to target = link building opportunities
- Domains linking to both = validate existing relationships
- Domains linking only to target = competitive advantage
- Top 20 link building opportunities with domain authority

### 7. New and Lost Backlinks

**DataForSEO only:** `backlinks_backlinks` with date filters for 30/60/90 day changes

**Verification Crawler:** For known links, verify current status with `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run verify_backlinks.py --target <url> --links <file> --json`

**Note:** Free sources cannot track new/lost links over time. If this section is requested without DataForSEO, inform the user: "Link velocity tracking requires the DataForSEO extension. Free sources provide point-in-time snapshots only."

**Red flags:**
- Sudden spike in new links (possible negative SEO attack)
- Sudden loss of many links (site penalty or content removal)
- Declining velocity over 3+ months (content not attracting links)

## Backlink Health Score

Calculate a 0-100 score. When mixing sources, apply confidence weighting:

| Factor | Weight | Sources (preference order) | Confidence |
|--------|--------|---------------------------|------------|
| Referring domain count | 20% | DataForSEO > Moz | 1.0 / 0.85 |
| Domain quality distribution | 20% | DataForSEO > Moz DA distribution | 1.0 / 0.85 |
| Anchor text naturalness | 15% | DataForSEO > Moz > Bing anchors | 1.0 / 0.85 / 0.70 |
| Toxic link ratio | 20% | DataForSEO > Moz spam score | 1.0 / 0.85 |
| Link velocity trend | 10% | DataForSEO only | 1.0 |
| Follow/nofollow ratio | 5% | DataForSEO > Bing details | 1.0 / 0.70 |
| Geographic relevance | 10% | DataForSEO > Bing country | 1.0 / 0.70 |

**Data sufficiency gate:** Count how many of the 7 factors have at least one data source available.
- **4+ factors with data:** Produce a numeric 0-100 score (redistribute missing weights proportionally)
- **Fewer than 4 factors:** Do NOT produce a numeric score. Instead display:
  ```
  Backlink Health Score: INSUFFICIENT DATA (X/7 factors scored)
  ```
  Show individual factor scores that ARE available with their source and confidence.
  Recommend: "Configure Moz API (free) for a scoreable profile. Run `/seo backlinks setup`"

### MUST NOT: score what you did not measure

**When Common Crawl is the only available source, you MUST NOT produce a numeric
score of any kind** -- not a health score, not a per-factor score, not an
"approximate" or "estimated" figure. Common Crawl supplies rank and presence
signals only. Report low-confidence rank/presence data and the literal string
`Not Assessed` in place of every number.

**A finding written with `source: not-assessed` MUST NOT carry a numeric score.**

A numeric score with fewer than 4 data sources is **misleading**: it implies poor
health when the reality is that we simply lack data.

### Validation gate (required, not optional)

This rule has been stated in this skill before and was violated anyway, so it is
now checkable. **Before writing any backlink output, run the validator:**

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run validate_backlink_report.py --report <report>.json --json
```

Pass the sources you actually collected (`cc_data`, `moz_data`, `bing_data`,
`dataforseo_data`, `scoring_factors`, and your `findings` list). The
`source_score_consistency` check fails the report with `status: FAIL` when:

- a numeric score is present but no scoreable source (Moz, Bing, or DataForSEO)
  supplied data -- i.e. the Common-Crawl-only case, and
- any finding marked `source: not-assessed` carries a numeric `score`, `value`,
  or `health_score`.

**If the validator returns `status: FAIL`, do not present the report.** Fix the
findings -- replace the offending numbers with `Not Assessed` -- and re-run until
it passes.

**Fallback cascade:**

2. Moz configured? → Use for DA/PA/spam/anchors (confidence: 0.85)
3. Bing configured? → Use for registered-property links and comparison only
   when both properties are accessible (confidence: 0.70)
4. Moz not configured but Keywords Everywhere is? → Use for a Profile Overview
   rank-only fallback (confidence: 0.60; single metric, no link counts/anchors)
5. Always: Common Crawl for domain-level metrics (confidence: 0.50)
6. Always: Verification crawler for known link checks (confidence: 0.95)
7. Nothing works? → "Run `/seo backlinks setup` to configure free APIs"
