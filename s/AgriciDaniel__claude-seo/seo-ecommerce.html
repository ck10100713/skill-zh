# 電商 SEO 分析

完整的商品頁優化、市集情報和競爭定價分析。可以單獨使用（頁面上 + schema），也可以搭配 DataForSEO Merchant API，取得即時的 Google Shopping 和 Amazon 資料。

## 指令

| 指令 | 用途 | 需要 DataForSEO？ |
|---------|---------|-------------|
| `/seo ecommerce <url>` | 對商品頁或商店做完整的電商 SEO 分析 | 選配 |
| `/seo ecommerce products <keyword>` | Google Shopping 競爭分析 | 必要 |
| `/seo ecommerce gaps <domain>` | 關鍵字缺口：自然搜尋 vs Shopping 的能見度 | 必要 |
| `/seo ecommerce schema <url>` | 商品 schema 的驗證與強化 | 不需要 |

## 1. 商品頁分析（不需要 DataForSEO）

抓取並解析任何商品頁，檢查頁面上的 SEO 品質。

### 工作流程

```
1. "${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run render_page.py <url> --mode auto → raw/rendered HTML
2. "${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run parse_html.py --url <url>   → SEO elements
3. Analyze product-specific signals (below)
```

### 商品 SEO 檢查清單

#### Title Tag
- [ ] 包含主要的商品關鍵字
- [ ] 包含品牌名稱
- [ ] 60 個字元以內（SERP 不會被截斷）
- [ ] 格式：`[Product Name] - [Key Feature] | [Brand]`

#### Meta Description
- [ ] 包含商品關鍵字 + 好處
- [ ] 包含價格或「from $XX」（會引發 rich snippet 的興趣）
- [ ] 有行動呼籲（Shop now、Buy、Free shipping）
- [ ] 155 個字元以內

#### 標題結構
- [ ] 單一個 H1，符合主要的商品名稱
- [ ] H2 涵蓋：功能、規格、評論、相關商品
- [ ] 商品的各個變體之間，沒有重複的 H1 tag

#### 商品圖片
- [ ] Alt 文字包含商品名稱 + 區別特徵
- [ ] 檔名有描述性（不是 `IMG_001.jpg`）
- [ ] 提供 WebP 格式（附 JPEG 備援）
- [ ] 每個商品至少 3 張圖片（主圖、細節、生活風格）
- [ ] 高解析度圖片：Google 建議商家列表至少 50K 像素（寬 x 高）；更大（例如 800px 以上）是常見的做法，不是規則
- [ ] 只對 above-the-fold 以下的圖片做 lazy loading

#### 內部連結
- [ ] 麵包屑導覽：Home > Category > Subcategory > Product
- [ ] 相關商品區塊（交叉銷售 / 向上銷售）
- [ ] 用富含關鍵字的錨點，連回類別頁
- [ ] 評論區塊連結到完整的評論頁（如果是分開的）

#### 內容品質
- [ ] 獨特的商品描述（不是複製貼上廠商的文案）
- [ ] 商品描述本文的字數 >= 200
- [ ] 有規格表（不只是散文）
- [ ] 頁面上有使用者評論（UGC 訊號）

### 評分

| 類別 | 權重 | 準則 |
|----------|--------|----------|
| Schema 完整度 | 25% | 必要 + 建議的 Product 欄位 |
| Title 與 meta | 15% | 關鍵字位置、長度、格式 |
| 圖片優化 | 20% | Alt 文字、格式、尺寸、數量 |
| 內容品質 | 20% | 獨特的描述、規格、評論 |
| 內部連結 | 10% | 麵包屑、相關商品、類別 |
| 技術 | 10% | 頁面速度、行動版渲染、canonical |

## 2. Google Shopping 情報（DataForSEO Merchant API）

來自 Google Shopping 結果的即時競爭分析。

### 成本護欄（必要）

每一次 Merchant API 呼叫之前：
```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_costs.py check merchant_google_products_search
```

- `"status": "approved"` -- 繼續
- `"status": "needs_approval"` -- 顯示成本，詢問使用者
- `"status": "blocked"` -- 停止，告知使用者

每次呼叫之後：
```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_costs.py log merchant_google_products_search <cost>
```

### 工作流程

```bash
# 商品搜尋：誰用什麼價格賣什麼
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_merchant.py search "<keyword>" --marketplace google

# 賣家分析：商家評分與主導程度
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_merchant.py sellers "<keyword>"

# 把結果正規化，方便分析
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_normalize.py results.json --module merchant
```

### 分析輸出

#### 定價情報
- 價格分布：最小值、最大值、中位數、P25、P75
- 價格離群值（偏離中位數超過 2 個標準差）
- 價格與評分的相關性
- 幣別正規化成 USD（或使用者指定的幣別）

#### 賣家版圖
- 依商品數量排名前 10 的賣家
- 商家評分的分布
- 免運費的普及程度
- 新賣家 vs 老牌賣家

#### 商品列表品質
- 排名前面的商品列表，標題的關鍵字模式
- 平均評分和評論數量的 benchmark
- 每個商品列表的圖片數量
- 供貨狀態的分布

完整的 API 參數細節，載入 `references/marketplace-endpoints.md`。

## 4. 市集關鍵字缺口

找出自然搜尋和 Shopping 能見度之間的落差。

### 工作流程

1. 透過 seo-dataforseo 抓取自然排名：
   對網域使用 `dataforseo_labs_google_ranked_keywords`
2. 透過 Merchant REST script 抓取 Google Shopping 的曝光（不是 MCP 工具；成本帳冊的 key 是 `merchant_google_products_search`）：
   對排名前面的自然搜尋關鍵字，使用 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run dataforseo_merchant.py search <keyword>`
3. 交叉對照結果

### 缺口類型

| 缺口類型 | 意義 | 動作 |
|----------|---------|--------|
| **只有自然搜尋** | 自然搜尋有排名，但沒有 Shopping 廣告 | 建立 Google Merchant Center feed，對這些關鍵字出價 |
| **只有 Shopping** | 有 Shopping 能見度，但自然搜尋很弱或沒有 | 為這些關鍵字建立內容（購買指南、比較頁） |
| **兩邊都有** | 兩個管道都看得到 | 優化：確保價格一致，強化 schema |
| **兩邊都沒有** | 兩邊都沒有能見度 | 除非搜尋量高，否則低優先 |

### 輸出格式

```
## Keyword Gap Analysis: example.com

### Opportunities: Organic → Shopping (12 keywords)
| Keyword | Organic Pos | Volume | CPC | Recommended Action |
|---------|------------|--------|-----|-------------------|

### Opportunities: Shopping → Organic (8 keywords)
| Keyword | Shopping Rank | Volume | CPC | Content Type Needed |
|---------|-------------|--------|-----|-------------------|
```

## 5. 商品 Schema 強化

依照 Google 目前的要求，驗證並產生 Product schema。

### 已確認的必要屬性（Google Merchant）

已確認的必要欄位是 `name`、`image` 和 `offers`；商家列表要用 `Offer`，不要用 `AggregateOffer`。商家列表要求 `price` 大於零，而且只要設定了 `price`，就要有 `priceCurrency`。

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "",
  "image": [""],
  "offers": {
    "@type": "Offer",
    "url": "",
    "priceCurrency": "USD",
    "price": "49.00",
    "availability": "https://schema.org/InStock"
  }
}
```

### 建議的屬性（強化 Rich Result）

- `sku` -- 商品識別碼
- `description`、`brand`、`offers.seller` -- 建議的脈絡欄位
- `gtin13` / `gtin14` / `mpn` -- 全球貿易識別碼
- `aggregateRating` -- 星等評分 + 評論數量
- `review` -- 個別評論（至少 1 則）
- `color`、`material`、`size` -- 變體屬性
- `shippingDetails` -- 附帶運費和送達時間的 ShippingDetails（也支援透過 `ShippingService` 設定商家層級的運送；運送/退貨可以在 Search Console 設定，不需要 Merchant Center 帳號）
- `hasMerchantReturnPolicy` -- 附帶類型和天數的 MerchantReturnPolicy
- `hasAdultConsideration` -- **成人導向的商品必填**（2026-05-20 新增到 Product variant / Merchant listing）；Google Search 只支援 `https://schema.org/SexualContentConsideration` 這個值
- `category` -- `Text`、`CategoryCode`，或兩者混用的陣列。商家自訂的商品類型用自訂文字，Google 商品類別則用 `CategoryCode`，搭配 Google 分類法的 URL 加上 `codeValue`。

### 驗證規則

1. `price` 必須是數字字串，不是「$29.99」（不能有貨幣符號）
2. `availability` 必須使用完整的 Schema.org URL 列舉值
3. `image` 應該是陣列，至少有 1 個高解析度圖片的 URL
4. `priceCurrency` 必須是 ISO 4217（USD、EUR、GBP）
5. 如果有 `brand`，`brand.name` 不能是空的，也不能是「N/A」
6. 特價期間使用 `validFrom`，加上 `validThrough` 或 `priceValidUntil` 其中之一，格式為 ISO 8601。知道的話，要包含時間和時區。
7. 如果有 `aggregateRating`：`ratingValue` 和 `reviewCount` 是必要的（商家列表文件列的是 `reviewCount`；評論摘要的文件也接受 `ratingCount`）
8. 在看得到的內容或結構化資料裡，不要放假評論，也不要放沒有揭露的有獎勵評論。要清楚且顯眼地揭露獎勵。

### Schema 評分

| 完整度 | 分數 |
|-------------|-------|
| 所有必要欄位 | 50/100 |
| + aggregateRating | 65/100 |
| + sku/gtin/mpn | 75/100 |
| + shippingDetails | 85/100 |
| + merchantReturnPolicy | 90/100 |
| + 評論（3 則以上） | 100/100 |

## UCP：Universal Commerce Protocol（已上線）

Google 發起的開放標準（和 Shopify、Etsy、Wayfair、Target、Walmart 共同開發；支付夥伴有 Visa/Mastercard/Stripe/Adyen/Amex），讓 AI agent 不需要一對一的整合，就能和商家探索、協商並交易。Google 確認了在 Search 的 AI Mode 裡，做對話式購買的第一個參考實作。更廣泛的 Universal Cart 推出細節，來自 Google I/O 2026 主題演講的報導；沒有在 Google 自己的來源上得到證實。ucp.dev 把 **2026-08-25** 列為最新的規格版本（Google 的商家指南仍然記載 2026-04-08），採用的是**以日期為準的版本編號**，不是 `1.0`；有兩條整合路徑：**Native**（預設）和 **Embedded**（核准的商家）。搭配 **AP2**（據報導正朝向 FIDO 治理發展）。標準來源：developers.google.com/merchant/ucp 和 ucp.dev。

已經在 **Google Merchant Center** 上、而且 Product schema 乾淨的商家，可以在 `/.well-known/ucp` 宣告 UCP profile，列出各項 capability（`dev.ucp.shopping.checkout`、`.fulfillment`、`.discount`）。稽核準則、capability 範例，以及和 AP2（Agent Payments Protocol）的關係，見 `references/ucp-universal-commerce-protocol.md`。

### 稽核指令

```bash
# 探索並驗證 UCP profile
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run ucp_check.py https://store.example.com --json

# 加上 endpoint 可達性探測（對每個宣告的 capability 做 HEAD）
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run ucp_check.py https://store.example.com --probe-endpoints --json
```

這個 script 會回傳：profile 是否存在、版本、宣告的 capability、結構性問題（缺少的欄位、未知的 capability ID），以及（用 `--probe-endpoints` 時）每個 endpoint 的可達性。被 SSRF 擋下的 endpoint 會明確回報。沒有 profile，回報成機會，不是失敗。UCP 本身已經上線；早期的是商家的廣泛採用。如果出現字面上的 `"version": "1.0"`，要標記為無效（UCP 的版本是以日期為準，例如 `2026-04-08`）。

## 錯誤處理

| 錯誤 | 原因 | 回應 |
|-------|-------|----------|
| 找不到 Product schema | 頁面沒有 JSON-LD | 分析頁面內容，產生建議的 schema |
| 缺少 DataForSEO 憑證 | 沒設定環境變數 | 不使用市集資料來執行分析，並註明這個限制 |
| 成本檢查被擋下 | 超過每日預算 | 告知使用者，提供只用免費資源的分析 |
| Shopping 結果是空的 | 這個關鍵字沒有商品 | 建議用更廣的關鍵字，檢查地區設定 |
| Amazon API 逾時 | 網路/限流 | 用退避重試，退回只用 Google |
| 無效的 URL | 輸入格式錯誤 | 透過 `google_auth.validate_url()` 驗證，顯示錯誤 |
| 非商品頁面 | URL 是類別/首頁 | 執行商店層級的檢查（UCP profile、類別結構、feed），並要求提供商品 URL，做商品層級的檢查 |

## 1. Product Page Analysis (No DataForSEO Needed)

Fetch and parse any product page for on-page SEO quality.

### Workflow

```
1. "${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run render_page.py <url> --mode auto → raw/rendered HTML
2. "${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run parse_html.py --url <url>   → SEO elements
3. Analyze product-specific signals (below)
```

### Product SEO Checklist

#### Title Tag
- [ ] Contains primary product keyword
- [ ] Includes brand name
- [ ] Under 60 characters (no truncation in SERPs)
- [ ] Format: `[Product Name] - [Key Feature] | [Brand]`

#### Meta Description
- [ ] Contains product keyword + benefit
- [ ] Includes price or "from $XX" (triggers rich snippet interest)
- [ ] Call-to-action present (Shop now, Buy, Free shipping)
- [ ] Under 155 characters

#### Heading Structure
- [ ] Single H1 matching primary product name
- [ ] H2s for: Features, Specifications, Reviews, Related Products
- [ ] No duplicate H1 tags across product variants

#### Product Images

## 5. Product Schema Enhancement

Validate and generate Product schema following Google's current requirements.

### Confirmed Required Properties (Google Merchant)

Confirmed required fields are `name`, `image`, and `offers`; use `Offer`, not `AggregateOffer`, for merchant listings. Merchant listings require a `price` greater than zero, and `priceCurrency` whenever `price` is set.

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "",
  "image": [""],
  "offers": {
    "@type": "Offer",
    "url": "",
    "priceCurrency": "USD",
    "price": "49.00",
    "availability": "https://schema.org/InStock"
  }
}
```

### Recommended Properties (Enhance Rich Results)

- `sku` -- product identifier
- `description`, `brand`, `offers.seller` -- recommended context fields
- `gtin13` / `gtin14` / `mpn` -- global trade identifiers
- `aggregateRating` -- star rating + review count
- `review` -- individual reviews (minimum 1)
- `color`, `material`, `size` -- variant attributes
- `shippingDetails` -- ShippingDetails with rate and delivery time (merchant-level shipping via `ShippingService` is also supported; shipping/returns can be set in Search Console without a Merchant Center account)
- `hasMerchantReturnPolicy` -- MerchantReturnPolicy with type and days
- `hasAdultConsideration` -- **required for adult-oriented products** (added 2026-05-20 to Product variant / Merchant listing); Google Search supports only the value `https://schema.org/SexualContentConsideration`
- `category` -- `Text`, `CategoryCode`, or an array mixing both. Use custom
  text for merchant-defined product types and `CategoryCode` with Google's
  taxonomy URL plus `codeValue` for Google Product Categories.

### Validation Rules

1. `price` must be a number string, not "$29.99" (no currency symbol)
2. `availability` must use full Schema.org URL enum
3. `image` should be array with >= 1 high-res image URL
4. `priceCurrency` must be ISO 4217 (USD, EUR, GBP)
5. If `brand` is present, `brand.name` must not be empty or "N/A"
6. Sale periods use `validFrom` plus either `validThrough` or
   `priceValidUntil`, in ISO 8601 format. Include time and timezone when known.
7. If `aggregateRating` present: `ratingValue` and `reviewCount` required (the merchant-listing docs list `reviewCount`; the review-snippet docs also accept `ratingCount`)
8. Do not include fake reviews or undisclosed incentivized reviews in visible
   content or structured data. Clearly and prominently disclose incentives.

### Schema Scoring

| Completeness | Score |
|-------------|-------|
| All required fields | 50/100 |
| + aggregateRating | 65/100 |
| + sku/gtin/mpn | 75/100 |
| + shippingDetails | 85/100 |
| + merchantReturnPolicy | 90/100 |
| + reviews (3+) | 100/100 |

## UCP: Universal Commerce Protocol (live)

Google-initiated open standard (co-developed with Shopify, Etsy, Wayfair,
Target, Walmart; payment partners Visa/Mastercard/Stripe/Adyen/Amex) for
letting AI agents discover, negotiate, and transact with merchants without
one-off integrations. Google confirms a first reference implementation for
conversational buying in AI Mode in Search. Broader Universal Cart rollout
details are reported from Google I/O 2026 keynote coverage; not confirmed on a
Google-owned source. ucp.dev lists **2026-08-25** as the latest spec release (Google's merchant
guide still documents 2026-04-08) in its **date-based versioning** scheme, not `1.0`; two integration paths: **Native**
(default) and **Embedded** (approved merchants). Pairs with **AP2** (reportedly
moving toward FIDO governance). Canonical: developers.google.com/merchant/ucp
and ucp.dev.

Merchants already on **Google Merchant Center** with clean Product schema can
declare a UCP profile at `/.well-known/ucp` listing capabilities
(`dev.ucp.shopping.checkout`, `.fulfillment`, `.discount`). See
`references/ucp-universal-commerce-protocol.md` for audit criteria,
capability examples, and the relationship to AP2 (Agent Payments Protocol).

### Audit command

```bash
# Discover and validate the UCP profile
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run ucp_check.py https://store.example.com --json

# With endpoint reachability probes (HEAD each declared capability)
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run ucp_check.py https://store.example.com --probe-endpoints --json
```

The script returns: profile presence, version, declared capabilities,
structural issues (missing fields, unknown capability IDs), and (with
`--probe-endpoints`) per-endpoint reachability. SSRF-blocked endpoints are
reported explicitly. Missing profile is reported as opportunity, not failure.
UCP itself is live; what's early is broad merchant adoption. Flag a literal
`"version": "1.0"` as invalid (UCP versions are date-based, e.g. `2026-04-08`).

## Error Handling

| Error | Cause | Response |
|-------|-------|----------|
| No Product schema found | Page lacks JSON-LD | Analyze page content, generate recommended schema |
| DataForSEO credentials missing | Env vars not set | Run analysis without marketplace data, note limitation |
| Cost check blocked | Daily budget exceeded | Inform user, offer free-only analysis |
| Empty Shopping results | No products for keyword | Suggest broader keyword, check location settings |
| Amazon API timeout | Network/rate limit | Retry with backoff, fall back to Google-only |
| Invalid URL | Malformed input | Validate via `google_auth.validate_url()`, show error |
| Non-product page | URL is category/homepage | Run the store-level checks (UCP profile, category structure, feeds) and ask for a product URL for the product-level checks |
