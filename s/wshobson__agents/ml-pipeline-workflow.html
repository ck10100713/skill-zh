# ML Pipeline Workflow

完整的端到端 MLOps pipeline 編排，從資料準備到模型部署。

## Overview

這個 skill 提供完整的指引，用來建構涵蓋整個生命週期的正式環境 ML pipeline：資料擷取 → 準備 → 訓練 → 驗證 → 部署 → 監控。

## When to Use This Skill

- 從零開始建立新的 ML pipeline
- 為 ML 系統設計工作流程編排
- 實作 資料 → 模型 → 部署 的自動化
- 建立可重現的訓練工作流程
- 建立以 DAG 為基礎的 ML 編排
- 把 ML 元件整合進正式環境系統

## What This Skill Provides

### Core Capabilities

1. **Pipeline Architecture**
   - 端到端工作流程設計
   - DAG 編排模式（Airflow、Dagster、Kubeflow）
   - 元件相依性與資料流
   - 錯誤處理與 retry 策略

2. **Data Preparation**
   - 資料驗證與品質檢查
   - 特徵工程 pipeline
   - 資料版本控管與 lineage
   - Train/validation/test 切分策略

3. **Model Training**
   - 訓練 job 編排
   - 超參數管理
   - 整合實驗追蹤
   - 分散式訓練模式

4. **Model Validation**
   - 驗證框架與指標
   - A/B 測試基礎設施
   - 效能退化偵測
   - 模型比較工作流程

5. **Deployment Automation**
   - 模型 serving 模式
   - Canary 部署
   - Blue-green 部署策略
   - Rollback 機制

### Reference Documentation

詳細指南請見 `references/` 目錄：

- **data-preparation.md** - 資料清理、驗證與特徵工程

### Production Workflow

1. **Data Preparation Phase**
   - 從來源擷取原始資料
   - 執行資料品質檢查
   - 套用特徵轉換
   - 為處理後的資料集做版本控管

2. **Training Phase**
   - 載入已版本化的訓練資料
   - 執行訓練 job
   - 追蹤實驗與指標
   - 儲存訓練好的模型

3. **Validation Phase**
   - 執行驗證測試套件
   - 與 baseline 比較
   - 產生效能報告
   - 核准部署

4. **Deployment Phase**
   - 封裝模型 artifact
   - 部署到 serving 基礎設施
   - 設定監控
   - 驗證正式環境流量

## Best Practices

### Pipeline Design

- **Modularity**：每個階段都應該能獨立測試
- **Idempotency**：重跑階段應該是安全的
- **Observability**：每個階段都要記錄指標
- **Versioning**：追蹤資料、程式碼與模型的版本
- **Failure Handling**：實作 retry 邏輯與警報

### Data Management

- 使用資料驗證函式庫（Great Expectations、TFX）
- 用 DVC 或類似工具為資料集做版本控管
- 記錄特徵工程的轉換
- 維持資料 lineage 追蹤

### Model Operations

- 把訓練與 serving 的基礎設施分開
- 使用 model registry（MLflow、Weights & Biases）
- 新模型採漸進式 rollout
- 監控模型效能飄移
- 保留 rollback 能力

### Deployment Strategies

- 從 shadow 部署開始
- 用 canary 發布做驗證
- 實作 A/B 測試基礎設施
- 設定自動 rollback 觸發條件
- 監控延遲與吞吐量

## Integration Points

### Orchestration Tools

- **Apache Airflow**：以 DAG 為基礎的工作流程編排
- **Dagster**：以 asset 為基礎的 pipeline 編排
- **Kubeflow Pipelines**：Kubernetes 原生的 ML 工作流程
- **Prefect**：現代的 dataflow 自動化

### Experiment Tracking

- MLflow 用於實驗追蹤與 model registry
- Weights & Biases 用於視覺化與協作
- TensorBoard 用於訓練指標

### Deployment Platforms

- AWS SageMaker：託管的 ML 基礎設施
- Google Vertex AI：GCP 部署
- Azure ML：Azure 雲端
- OCI Data Science：Oracle Cloud Infrastructure 部署
- Kubernetes + KServe：不綁定雲端的 serving

## Best Practices

### Pipeline Design

- **Modularity**: Each stage should be independently testable
- **Idempotency**: Re-running stages should be safe
- **Observability**: Log metrics at every stage
- **Versioning**: Track data, code, and model versions
- **Failure Handling**: Implement retry logic and alerting

### Data Management

- Use data validation libraries (Great Expectations, TFX)
- Version datasets with DVC or similar tools
- Document feature engineering transformations
- Maintain data lineage tracking

### Model Operations

- Separate training and serving infrastructure
- Use model registries (MLflow, Weights & Biases)
- Implement gradual rollouts for new models
- Monitor model performance drift
- Maintain rollback capabilities

### Deployment Strategies

- Start with shadow deployments
- Use canary releases for validation
- Implement A/B testing infrastructure
- Set up automated rollback triggers
- Monitor latency and throughput
