# Visual Edit Precision

## Overview

當變更需求附帶視覺脈絡（元素選取、標註、截圖）時，要做有針對性的最小幅度修改。精準比企圖心重要：只改被指到的東西，其他都保留。

## Process

提供視覺脈絡時：

1. **IDENTIFY** - 被指到的確切元素是哪些？哪個元件檔案擁有它們？
2. **SCOPE** - 只改被指到的東西。不要重構周圍的程式碼。
3. **PRESERVE** - 保留既有的樣式、class 和行為。只修改被要求的部分。
4. **TARGETED** - 做能達成視覺結果的最小 CSS/markup 變更。
5. **VERIFY** - 確認變更能正確渲染，而且沒有副作用。

## Key Principles

### Precision Over Ambition

視覺脈絡給你的是一個特定的元素。不要：
- 只被要求改一個樣式，卻重構整個元件
- 只被指到外觀，卻去改元件的 API
- 只選了視覺部分，卻去動邏輯

要：
- 找出被選取元素確切的檔案和行號
- 做能達成所述視覺變更的最小修改
- 保留所有既有的行為、事件處理函式和無障礙設定

### Multiple Edits

收到多個視覺編輯時：
- 每一個各自針對自己的元素，彼此獨立
- 不用等某一個做完才處理另一個
- 如果兩個編輯衝突（同一個元素、不同的要求），處理最新的那個

## Common Mistakes

- 使用者只指了一個按鈕，卻重寫整個元件
- 只需要調整一個元素的顏色，卻去改全域設定
- 為了配合選取範圍而加上固定寬度，破壞了響應式行為
- 忽略特定性（使用者指的是一張卡片，agent 卻改了所有卡片）
- 在視覺編輯過程中移除無障礙屬性（aria-*、role、tabindex）
