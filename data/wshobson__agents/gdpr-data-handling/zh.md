# GDPR 資料處理

實作符合 GDPR 的資料處理、同意管理與隱私控制的實務指南。

## 什麼時候用這個 Skill

- 建構處理歐盟個人資料的系統
- 實作同意管理
- 處理資料當事人請求（DSR）
- 進行 GDPR 合規審查
- 設計以隱私為先的架構
- 建立資料處理協議

## 核心概念

### 1. 個人資料類別

| 類別                   | 範例                        | 保護等級           |
| ---------------------- | --------------------------- | ------------------ |
| **基本資料**           | 姓名、email、電話           | 標準               |
| **敏感資料（第 9 條）** | 健康、宗教、種族            | 明確同意           |
| **刑事資料（第 10 條）** | 定罪、犯罪紀錄              | 官方機關           |
| **兒童資料**           | 16 歲以下的資料             | 家長同意           |

### 2. 處理的法律依據

```
第 6 條：合法依據：
├── 同意：自願給予、具體、已充分告知
├── 契約：履行契約所必需
├── 法律義務：法律要求
├── 重大利益：保護某人的生命
├── 公共利益：公務職能
└── 正當利益：需與當事人權利取得平衡
```

### 3. 資料當事人的權利

```
存取權（第 15 條）            ─┐
更正權（第 16 條）             │
刪除權（第 17 條）             │ 必須在
限制處理權（第 18 條）         │ 一個月內回應
可攜權（第 20 條）             │
異議權（第 21 條）            ─┘
```

## 最佳實務

### 該做的

- **最小化資料蒐集**：只蒐集需要的
- **每樣東西都要記錄**：處理活動、法律依據
- **加密個資**：靜態與傳輸中都要
- **實作存取控制**：以需要知道為原則
- **定期稽核**：持續驗證合規性

### 不該做的

- **不要預先勾選同意方塊**：必須是 opt-in
- **不要把同意綁在一起**：不同目的要分開
- **不要無限期保存**：要定義並落實保存期限
- **不要忽略 DSAR**：必須在 30 天內回應
- **不要在沒有保障措施下傳輸**：需有 SCC 或充分性認定
