# 付費媒體計畫

1. 讀 setup 設定檔、商業經濟效益、證據、目前的帳號狀態，以及選配輸入的相關產業範本。
2. 定義目標、客戶、offer、轉換、價值、限制、地區、受管制類別、時間範圍和成功準則。
3. 從第一原理評估各通路的角色與排除項目；不要要求每個支援的平台都要用。如果是十二平台契約以外的通路，要載入 `ads/references/additional-platforms.md`（從 plugin root 解析，也就是包含 `ads/` 和 `skills/` 的那層目錄；獨立安裝的話，從 skills 目錄解析），除非它最新的購買、資格、衡量和創意證據齊備，否則只回傳研究線索。
4. 在提出 Meta 的預算、學習階段預期、出價、整併或成效預測之前，先依照 `skills/ads-meta/SKILL.md` 裡的契約，蒐集帳號、Pixel 和轉換的冷啟動維度。只要有任何一個維度是冷啟動或 `unknown`，就規劃衡量驗證、明確的創意假設、分階段且可逆的測試和信心標籤；不要把成熟帳號的 benchmark 套用在缺少的歷史上。
5. 指定廣告活動架構、受眾策略、創意系統、預算與 pacing、衡量、實驗、政策控管和營運節奏。
6. 把前置條件分階段，涵蓋上線前、學習、優化和放大。
7. 每個行動都要指定負責人、時程、相依項目、護欄、證據、成功衡量，以及 rollback 或退出條件。
8. 回傳標準 JSON，並產生要求的給人看的計畫。

計畫只是建議。它只有透過 launch 或 optimize 的 mutation gate，才會變成帳號變更。
