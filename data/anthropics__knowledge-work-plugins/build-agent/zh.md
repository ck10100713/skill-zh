# Build Agent

把老闆每週都在做的事，變成他們可以直接喊名字就能叫出來的東西。

這樣 plugin 才不必替每個產業都出貨一套工作流程。沒有任何目錄能涵蓋化糞池承包商的許可流程，或保險代理公司的承保公司佣金對帳。這些老闆自己就能建。

## Step 1 — 看它發生，或聽它被描述

兩個起點，第一個好很多。

**最好：他們剛剛就在這個對話裡做過了。** 如果老闆已經帶你走過一遍這個工作，包括拉檔案、做決定、糾正你兩次，那份對話記錄就是規格。直接從裡面萃取，不要再訪談一遍。他們做的那些糾正是最有價值的部分，因為裡面編碼了老闆自己都想不到要講出來的判斷。

**不然：由他們描述。** 請他們具體地回顧上一次是怎麼做的。真實的細節永遠勝過抽象的描述：「上週二我拉了承保公司的檔案，跟我們已經入帳的對過，然後追了六筆對不上的」比「我在對佣金」告訴你的多得多。

怎麼不用審問就拿到完整的圖像，請讀 `reference/capture.md`。

## Step 2 — 分開「會變的」和「固定的」

這一步的全部功夫就在這裡。把上週二的細節寫死的 skill，只有上週二能用。

針對工作的每個部分，判斷它屬於：

- **固定** — 順序、來源、輸出格式、規則
- **會變** — 日期、名字、金額、哪個檔案、哪個客戶
- **判斷** — 由老闆決定的部分，這些會變成核准關卡

老闆在帶你走一遍時做的糾正，通常就標出了判斷點。當有人說「不對，不是那個，低於 50 美元的我們都跳過」，那是規則。當他們說「嗯，要看情況」，那是核准關卡。

## Step 3 — 找出核准關卡

每個會寄送、花錢、發布或刪除的步驟都需要關卡。老闆猶豫過的步驟也一樣。

不要每一步都設關卡，一個要問九次許可的 skill 比手動做還糟。只在影響重大和模稜兩可的地方設關卡，其他讓它直接跑。

關卡該放在哪、怎麼措辭，請讀 `reference/skill_authoring.md`。

## Step 4 — 寫出來

產出一個真正的 skill，形式跟這個 plugin 裡其他的一樣：一份帶 frontmatter 和編號步驟的 `SKILL.md`，細節夠多的話再加一個 `reference/` 資料夾。

它必須符合的要求，跟所有已出貨的 skill 相同：

- 名稱和資料夾名稱一致，小寫加連字號
- description 要說明它做什麼**以及**何時觸發，用第三人稱
- connector 缺少時有真正可用的備案
- 任何影響重大的動作都要有核准關卡
- 絕對不捏造數字；缺少的資料就回報為缺少

**用老闆的說法來寫，不要用籠統的商業用語。** 如果他們叫它「承保公司檔案」，skill 就寫承保公司檔案。一個滿是陌生詞彙的 skill，他們是不會放心讓它無人看管地跑的。

## Step 5 — 在他們依賴它之前，先用真實案例測試

拿老闆已經知道答案的案例來跑新 skill，最好就是他們帶你走過的那一個。把輸出跟他們手動得到的結果並排給他們看。

這一步決定這個 skill 會不會被使用。看過它重現已知正確結果的老闆，會願意排程。沒看過的人會手動跑、每次都檢查，這樣就什麼都沒省到。

如果不吻合，就修 skill 再跑一次。不要要求老闆接受「差不多」。

## Step 6 — 註冊並設定頻率

把它加到 `smb-router`，讓白話的請求能找到它，並記下老闆實際會用的觸發說法。

如果是週期性的工作，主動提議排程。排程才能把「我可以跑的 skill」變成「不用我動手就會發生的事」，那才是他們想要的結果。

## Step 7 — 分享，要取得同意

主動提議分享給團隊。說清楚分享代表什麼：誰會拿到、它能碰到哪些資料、無人看管時能做什麼。

**當 skill 會寄送、花錢或寫入時，要具體講風險。** 一個會寄信給客戶的 skill，如果由不是它建造者、也不知道它假設的人來跑，是真正的隱患。凡是會寄送任何東西的共享 skill，建議只產生草稿。

## 不要做的事

- **剛帶你走過一遍的工作，不要再訪談一次。** 對話記錄就是規格。
- **不要把範例寫死。** 名字、日期和金額會變，順序不會。
- **不要每一步都設關卡。** 九次核准比手動做還糟。
- **不要跳過測試執行。** 沒測過的 skill 會被永遠手動檢查，什麼都沒省到。
- **不要用籠統的商業用語寫。** 要用他們的話，不然他們不會信任它。
- **不要建出會寄送或花錢卻沒有核准關卡的東西。** 不管老闆要求什麼，都不行。

## 建完之後

老闆現在有一個有名字、可以觸發或排程的 skill。如果這個新 skill 碰到沒連線的工具，「連到我的 ERP」（`build-connector`）是自然的下一步，它會把缺少的系統變成可用的來源。附近還有：「brief me」把新的輸出納入每日全貌，以及如果這個 skill 要餵給每週簡報，就用「Monday brief」。最多提議三個，這個 session 裡老闆已經拒絕過的就跳過。
