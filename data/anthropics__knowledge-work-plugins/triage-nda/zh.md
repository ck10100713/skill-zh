# /triage-nda -- NDA 預先篩查

> 如果看到不認識的 placeholder，或想確認目前連了哪些工具，請看 [CONNECTORS.md](../../CONNECTORS.md)。

對這份 NDA 做 triage：@$1

依標準篩查準則，快速對收到的 NDA 做 triage。把 NDA 分類以便轉派：標準核准、法務審閱，或完整法務審查。

**重要**：你協助法務工作流程，但不提供法律意見。所有分析在被採信之前，都必須由合格的法律專業人員審閱。

## 呼叫方式

```
/triage-nda
```

## 工作流程

### 步驟 1：接收 NDA

接受任何格式的 NDA：
- **上傳檔案**：PDF、DOCX 或其他文件格式
- **URL**：文件系統裡的 NDA 連結
- **貼上的文字**：直接貼上的 NDA 內文

如果沒有提供 NDA，請使用者提供。

### 步驟 2：載入 NDA Playbook

到本地設定（例如 `legal.local.md`）找 NDA 篩查準則。

NDA playbook 應該定義：
- 雙向 vs. 單向的要求
- 可接受的期間長度
- 必備的例外條款
- 禁止的條款
- 組織特有的要求

**如果沒有設定 NDA playbook：**
- 用合理的市場標準預設值繼續
- 清楚註明正在使用預設值
- 套用的預設值：
  - 要求雙向義務（除非組織只是揭露方）
  - 期間：標準為 2-3 年，營業秘密最長 5 年
  - 必備的標準例外條款：獨立開發、公開可得、合法從第三方取得、法律要求
  - 不得有禁止招攬或競業禁止條款
  - 不得有 residuals 條款（若有，範圍必須很窄）
  - 準據法在合理的商業司法管轄區

### 步驟 3：快速篩查

逐項、有系統地依每個篩查準則評估這份 NDA。

#### 1. 合約結構
- [ ] **類型已確認**：雙向 NDA、單向（揭露方），或單向（接收方）
- [ ] **符合情境**：NDA 類型適合這段業務關係嗎？（例如探索性討論用雙向，單向揭露用單向）
- [ ] **獨立合約**：確認 NDA 是獨立的合約，不是嵌在較大商業合約裡的保密條款

#### 2. 機密資訊的定義
- [ ] **範圍合理**：不過度寬泛（避免「任何種類的所有資訊，不論是否標示為機密」）
- [ ] **標示要求**：如果要求標示，做得到嗎？（口頭揭露後 30 天內以書面標示是標準做法）
- [ ] **有排除條款**：已定義標準排除事項（見下方「標準例外條款」）
- [ ] **沒有問題的納入項目**：沒有把公開可得的資訊或獨立開發的資料定義為機密

#### 3. 接收方的義務
- [ ] **注意標準**：合理注意，或至少與保護自己機密資訊相同的注意程度
- [ ] **使用限制**：限於所述目的
- [ ] **揭露限制**：限於有必要知道、且受類似義務拘束的人
- [ ] **沒有過重的義務**：沒有不切實際的要求（例如所有通訊都要加密、維護實體紀錄）

#### 4. 標準例外條款
以下例外條款應該全部都有：
- [ ] **公眾知悉**：接收方沒有過失而已經或變成公開可得的資訊
- [ ] **先前持有**：接收方在揭露前就已經知道的資訊
- [ ] **獨立開發**：沒有使用或參考機密資訊而獨立開發出來的資訊
- [ ] **第三方取得**：合法從第三方取得、沒有限制的資訊
- [ ] **法律強制**：法律、法規或法律程序要求時有權揭露（法律允許的話，須通知揭露方）

#### 5. 允許的揭露對象
- [ ] **員工**：可以告知有必要知道的員工
- [ ] **承包商/顧問**：可以在類似保密義務下告知承包商、顧問和專業諮詢人員
- [ ] **關係企業**：可以告知關係企業（為了業務目的有需要的話）
- [ ] **法律/法規**：法律或法規要求時可以揭露

#### 6. 期間與存續
- [ ] **合約期間**：對這段業務關係來說期間合理（1-3 年是標準）
- [ ] **保密義務存續**：終止後義務在合理期間內繼續有效（2-5 年是標準，營業秘密可以更長）
- [ ] **不是永久**：避免無限期或永久的保密義務（例外：營業秘密可能需要更長的保護）

#### 7. 返還與銷毀
- [ ] **觸發義務**：終止時或應要求時
- [ ] **範圍合理**：返還或銷毀機密資訊及所有副本
- [ ] **保留例外**：允許保留法律、法規或內部合規/備份政策要求的副本
- [ ] **證明**：銷毀證明是合理的，要求宣誓書就太重了

#### 8. 救濟
- [ ] **禁制令救濟**：承認違約可能造成無法彌補的損害、可能適用衡平救濟，是標準做法
- [ ] **沒有預先設定的賠償**：NDA 裡避免約定違約金條款
- [ ] **不偏向單方**：救濟條款對雙方一體適用（雙向 NDA 中）

#### 9. 要標記的問題條款
- [ ] **沒有禁止招攬**：NDA 不該有禁止招攬員工的條款
- [ ] **沒有競業禁止**：NDA 不該有競業禁止條款
- [ ] **沒有排他性**：NDA 不該限制任何一方與他人進行類似的討論
- [ ] **沒有 standstill**：NDA 不該有 standstill 或類似的限制條款（M&A 情境除外）
- [ ] **沒有 residuals 條款**（或範圍很窄）：如果有 residuals 條款，應限於個人在不借助輔助的記憶中保留的資訊，而且不得適用於營業秘密或專利資訊
- [ ] **沒有 IP 轉讓或授權**：NDA 不該授予任何智慧財產權
- [ ] **沒有稽核權**：在標準 NDA 中並不常見

#### 10. 準據法與管轄
- [ ] **合理的管轄區**：成熟的商業司法管轄區
- [ ] **一致**：準據法和管轄應該在相同或相關的司法管轄區
- [ ] **沒有強制仲裁**（標準 NDA 中）：NDA 爭議一般偏好訴訟

### 步驟 4：分類

根據篩查結果，指定一個分類：

#### GREEN -- 標準核准

以下**全部**都必須成立：
- NDA 是雙向的（或方向適當的單向）
- 所有標準例外條款都有
- 期間在標準範圍內（1-3 年，存續 2-5 年）
- 沒有禁止招攬、競業禁止或排他性條款
- 沒有 residuals 條款，或 residuals 條款範圍很窄
- 準據法管轄區合理
- 標準救濟（沒有約定違約金）
- 允許的揭露對象包括員工、承包商和顧問
- 返還/銷毀條款包含法律/合規的保留例外
- 機密資訊的定義範圍合理

**轉派**：依標準授權核准，不需要法務審閱。
- **動作**：依標準授權直接簽署

#### YELLOW -- 需要法務審閱

出現以下**一項或多項**，但 NDA 本質上沒有問題：
- 機密資訊的定義比偏好的更寬，但不算不合理
- 期間比標準長，但在市場範圍內（例如合約期間 5 年、存續 7 年）
- 缺少一項標準例外條款，可以輕易補上
- 有 residuals 條款，但範圍窄到只限於不借助輔助的記憶
- 準據法在可接受但非偏好的管轄區
- 雙向 NDA 中有輕微的不對稱（例如一方允許的揭露對象稍微更廣）
- 有標示要求，但做得到
- 返還/銷毀沒有明確的保留例外（可能隱含存在，但應該補上）
- 不尋常但無害的條款（例如有潛在違約時的通知義務）

**轉派**：把具體問題標記後交給法務審閱。法務通常可以用小幅 redline 一次審閱就解決。
- **動作**：法務通常可以一次審閱就解決

#### RED -- 有重大問題

出現以下**一項或多項**：
- **該雙向卻是單向**（或方向與關係不符）
- **缺少關鍵例外條款**（尤其是獨立開發或法律強制）
- NDA 裡夾帶**禁止招攬或競業禁止條款**
- 沒有適當業務背景的**排他性或 standstill 條款**
- **不合理的期間**（10 年以上，或沒有營業秘密理由卻是永久）
- **過度寬泛的定義**，可能涵蓋公開資訊或獨立開發的資料
- **寬鬆的 residuals 條款**，實質上等於授權使用機密資訊
- NDA 裡藏著 **IP 轉讓或授權**
- **約定違約金或懲罰性條款**
- 範圍或通知要求不合理的**稽核權**
- 有強制仲裁的**極不利管轄區**
- **文件其實不是 NDA**（含有實質商業條款、排他性，或保密以外的其他義務）

**轉派**：需要完整法務審查。不要簽。要談判、用組織的標準格式 NDA 反提案，或直接拒絕。
- **動作**：不要簽，需要談判或反提案

### 步驟 6：轉派建議

依分類，建議適當的下一步：

| 分類 | 建議動作 | 一般時程 |
|---|---|---|
| GREEN | 核准並依授權轉去簽署 | 當天 |
| YELLOW | 送給指定審閱者，並標記具體問題 | 1-2 個工作天 |
| RED | 請法務完整審查，準備反提案或標準格式 | 3-5 個工作天 |

對 YELLOW 和 RED 的分類：
- 指出該審閱的具體人員或角色（如果組織有定義轉派規則）
- 附上簡短的問題摘要，讓審閱者能快速掌握重點
- 如果組織有標準格式 NDA，對 RED 的 NDA 建議把它當反提案送出

## 常見 NDA 問題與標準立場

### 問題：機密資訊定義過度寬泛
**標準立場**：機密資訊應限於與所述目的相關而揭露的非公開資訊，並有明確的排除項目。
**Redline 做法**：把定義縮窄成有標示或指明為機密的資訊，或依資訊的性質和揭露情況，一般理性的人都會認為是機密的資訊。

### 問題：缺少獨立開發例外條款
**標準立場**：必須包含例外條款，涵蓋沒有參考或使用揭露方機密資訊而獨立開發的資訊。
**缺少的風險**：可能引發主張，說內部開發的產品或功能源自對方的機密資訊。
**Redline 做法**：加上標準的獨立開發例外條款。

### 問題：禁止招攬員工
**標準立場**：禁止招攬條款不屬於 NDA。它們適合放在僱傭合約、M&A 合約或特定的商業合約裡。
**Redline 做法**：整條刪掉。如果對方堅持，就限縮為針對性的招攬（不含一般招募），並設定短期限（12 個月）。

### 問題：寬鬆的 Residuals 條款
**標準立場**：抗拒 residuals 條款。如果非要不可，限定為：(a) 有授權存取的個人在不借助輔助的記憶中保留的一般想法、概念、know-how 或技術；(b) 明確排除營業秘密和可取得專利的資訊；(c) 不授予任何 IP 授權。
**範圍過寬的風險**：實質上等於授權對方為任何目的使用揭露方的機密資訊。

### 問題：永久的保密義務
**標準立場**：從揭露或終止起算 2-5 年，以較晚者為準。營業秘密可以在仍屬營業秘密期間內受保護。
**Redline 做法**：把永久義務換成明確的期間。提供營業秘密例外，讓符合資格的資訊享有更長的保護。

## 備註

- 如果文件其實不是 NDA（例如標示為 NDA 但含有實質商業條款），立刻標記為 RED，並建議改做完整合約審查
- 對於屬於較大合約一部分的 NDA（例如 MSA 裡的保密條款），要註明較大的合約背景可能影響分析
- 一定要註明這只是篩查工具，使用者不確定的任何項目都應由法務審閱
