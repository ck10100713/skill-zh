# 成效報告（Performance Report）

> 如果看到不熟的佔位符，或需要確認目前連了哪些工具，請見 [CONNECTORS.md](../../CONNECTORS.md)。

產生行銷成效報告，包含關鍵指標、趨勢分析、洞察和優化建議。

## 觸發

使用者執行 `/performance-report`，或要求行銷報告、成效分析、活動結果或指標摘要。

## 輸入

1. **報告類型**：判斷使用者需要哪一種報告：
   - **活動報告（Campaign report）**：某個特定活動的成效
   - **通路報告（Channel report）**：某個特定通路（email、社群、付費、SEO 等）的整體成效
   - **內容成效（Content performance）**：各內容的表現如何
   - **整體行銷報告（Overall marketing report）**：跨通路摘要（每週、每月、每季）
   - **自訂（Custom）**：使用者自訂的範圍

2. **時間區間**：報告的涵蓋期間（上週、上個月、上一季、自訂日期範圍）

3. **資料來源**：
   - 如果 ~~marketing analytics 已連接，先找出有哪些帳號和平台可用，再自動拉取成效資料
   - 如果 ~~product analytics 已連接：自動拉取成效資料
   - 如果沒連接：請使用者提供指標。提示語：「Please paste or share your performance data. I can work with spreadsheets, CSV data, dashboard screenshots described in text, or just the key numbers.」

4. **比較期間**（選填）：前一期或年對年，提供趨勢脈絡

5. **利害關係人受眾**（選填）：誰會讀這份報告（主管摘要風格 vs. 詳細的分析師視角）

## 報告結構

### 1. 主管摘要
- 用 2 到 3 句話概述該期間的成效
- 重點指標，附趨勢方向（跟前一期比上升／下降／持平）
- 一個關鍵的成果，和一個需要關注的地方

### 2. 關鍵指標 Dashboard

用摘要表呈現核心指標：

| Metric | This Period | Prior Period | Change | Target | Status |
|--------|------------|--------------|--------|--------|--------|

狀態指示：
- On track（達標或超越目標）
- At risk（低於目標但在可接受範圍內）
- Off track（明顯低於目標）

#### 依報告類型的指標

**活動報告：**
- 曝光與觸及
- 點擊率（CTR）
- 轉換率
- 每次獲客成本（CPA）
- 廣告投資報酬率（ROAS）或 ROI
- 總轉換數／註冊數／名單數

**通路報告（Email）：**
- 寄出、送達、退信的 email 數
- 開信率
- 點擊率
- 退訂率
- 轉換率

**通路報告（社群）：**
- 曝光與觸及
- 互動率（按讚、留言、分享）
- 追蹤者成長
- 點擊率
- 表現最好的貼文

**通路報告（付費）：**
- 花費
- 曝光與點擊
- CTR
- CPC 與 CPM
- 轉換與 CPA
- ROAS

**通路報告（SEO／自然流量）：**
- 自然搜尋工作階段（sessions）
- 關鍵字排名（變動）
- 已索引的頁面數
- 新獲得的反向連結
- 表現最好的頁面

**內容成效：**
- 頁面瀏覽量與不重複訪客
- 頁面停留時間
- 跳出率
- 社群分享
- 歸因於內容的轉換
- 表現最好和最差的內容

**整體行銷報告：**
- 產生的總名單數
- 行銷合格名單（MQL）
- 對 pipeline 的貢獻
- 客戶獲取成本（CAC）
- 逐通路摘要

### 3. 趨勢分析
- 該期間的成效趨勢（週對週或月對月）
- 值得注意的轉折點及成因
- 觀察到的季節性或週期性模式
- 與標竿或目標比較

### 4. 有效的做法
- 前 3 到 5 個成果，附具體資料
- 這些為什麼表現好（假設）
- 如何複製或擴大

### 5. 需要改進的地方
- 後 3 到 5 個表現不佳的項目，附具體資料
- 表現不佳的假設
- 建議的修正

### 6. 洞察與觀察
- 光看指標看不出來的資料模式
- 受眾行為洞察
- 引起共鳴的內容或創意主題
- 可能影響成效的外部因素（季節性、新聞、競爭對手動作）

### 7. 建議
每一項建議：
- 要做什麼
- 為什麼（連結到資料中的某個具體洞察）
- 預期影響（高、中、低）
- 實作所需的努力（高、中、低）
- 優先順序（立即、下一個 sprint、下一季）

用 2x2 矩陣格式排列建議的優先順序：

| | Low Effort | High Effort |
|---|---|---|
| **High Impact** | Do first | Plan for next sprint |
| **Low Impact** | Do if time allows | Deprioritize |

### 8. 下一期的重點
- 接下來這一期的前 3 個優先事項
- 要執行的測試或實驗
- 關鍵指標的目標

## 依頻率分類的報告範本

### 每週行銷報告
給團隊站會快速掃過的格式：
- **前 3 個指標**，附週對週變化
- 本週**有效的做法**（1 到 2 個重點，附資料）
- **需要關注的地方**（1 到 2 個重點，附資料）
- **本週優先事項**（3 到 5 個行動項目）

### 每月行銷報告
標準的利害關係人報告：
1. 主管摘要（3 到 5 句）
2. 關鍵指標 dashboard（表格，附月對月和目標比較）
3. 逐通路的成效摘要
4. 活動亮點與結果
5. 哪些有效、哪些沒效（附假設）
6. 建議與下個月的優先事項
7. 預算花費 vs. 計畫

### 季度業務檢視（QBR）
給管理層的策略檢視：
1. 本季成效 vs. 目標
2. 年初至今的軌跡
3. 通路 ROI 分析
4. 活動成效摘要
5. 競爭與市場觀察
6. 下一季的策略建議
7. 預算申請與分配計畫
8. 關鍵實驗與學到的事

### Dashboard 設計原則
- 以對應到商業目標的指標領頭（不是虛榮指標）
- 呈現隨時間的趨勢，不要只有單一時間點的快照
- 納入比較脈絡：前一期、目標、標竿
- 使用一致的顏色編碼：綠色（on track）、黃色（at risk）、紅色（off track）
- 依漏斗階段或商業問題為指標分組
- Dashboard 維持在一頁／一個畫面，細節放進附錄
- 更新頻率要配合決策頻率（付費是即時，內容是每週）

## 趨勢分析與預測

### 辨識趨勢
分析成效資料時，要找：

1. **方向性趨勢**：這個指標在 4 期以上是否持續上升、下降或持平？
2. **轉折點**：成效在哪裡改變方向，當時發生了什麼？
3. **季節性**：依星期幾、月份或季度是否有可預測的模式？
4. **異常**：一次性的暴增或暴跌，成因是什麼，會不會重現？
5. **領先指標**：哪些指標先動，並能預測未來結果？

### 趨勢分析流程
1. 把指標隨時間畫成圖（至少 8 到 12 個資料點才算有意義的趨勢）
2. 找出整體方向（向上、向下、持平、週期性）
3. 計算變化速率（是加速還是減速？）
4. 疊上重要事件（推出的活動、產品變更、市場事件）
5. 跟標竿或目標比較
6. 找出與其他指標的相關性
7. 對因果關係提出假設（並規劃測試去驗證）

### 簡單的預測方法
- **線性外推**：把目前的趨勢線往前延伸（適用於穩定的指標）
- **移動平均**：平均最近 3 到 6 期，把雜訊平滑掉
- **年對年比較**：用去年的模式當基準，再依成長率調整
- **漏斗運算**：從輸入預測輸出（例如，如果我們以 Y 的轉換率產生 X 個名單，就會得到 Z 位客戶）
- **情境建模**：建立最佳、預期和最差三種情況的推估

### 預測的注意事項
- 短期預測（1 到 3 個月）比長期預測可靠
- 根據少於 12 個資料點做的預測，要標示為低信心
- 外部因素（市場變化、競爭對手動作、經濟變動）可能讓依趨勢做的預測失效
- 預測一律以區間呈現，不要給精確數字

## 歸因建模基礎

### 什麼是歸因？
歸因（Attribution）決定哪些行銷接觸點該得到轉換的功勞。這很重要，因為買家在轉換之前，通常會接觸多個通路。

### 常見的歸因模型

| 模型 | 運作方式 | 最適合 | 限制 |
|-------|-------------|----------|------------|
| 最後接觸（Last touch） | 100% 功勞給轉換前的最後一次互動 | 了解最終的轉換觸發點 | 忽略知名度和培養 |
| 首次接觸（First touch） | 100% 功勞給第一次互動 | 了解漏斗頂端的效果 | 忽略培養和轉換的推動力 |
| 線性（Linear） | 所有接觸點平均分配功勞 | 公平呈現所有通路 | 無法反映相對影響力 |
| 時間衰減（Time decay） | 越接近轉換的接觸點得到越多功勞 | 偏重近期互動的平衡視角 | 可能低估知名度的貢獻 |
| 位置式（U 型） | 40% 給首次、40% 給最後、20% 分給中間 | 同時重視發現與轉換 | 權重有些武斷 |
| 資料驅動（Data-driven） | 依轉換模式用演算法分配功勞 | 最準確的呈現 | 需要大量資料 |

### 歸因的實務指引
- 如果還沒有任何模型，就從最後接觸歸因開始，它最簡單，也最有可行動性
- 比較首次接觸和最後接觸，了解哪些通路帶動知名度、哪些帶動轉換
- 對大多數 B2B 公司，位置式（U 型）是一個合理的折衷
- 資料驅動歸因需要很高的轉換量，才具有統計意義
- 沒有任何模型是完美的，歸因要當作方向參考，不要當作絕對真理
- 多點接觸歸因比單點接觸好，但任何模型都比沒有好

### 歸因的陷阱
- 不要根據單點接觸歸因，孤立地優化某一個通路
- 知名度通路（展示廣告、社群、公關）在最後接觸模型裡永遠看起來很差
- 轉換通路（搜尋、再行銷）在首次接觸模型裡永遠看起來很差
- 自述式歸因（「你是怎麼知道我們的？」）能提供有用的質性色彩，但作為量化資料並不可靠
- 跨裝置和跨通路追蹤的缺口，代表歸因資料永遠是不完整的

## 優化建議框架

### 優化流程
1. **辨識**：哪些指標低於目標或標竿？
2. **診斷**：問題出在漏斗的哪裡？（曝光、點擊、轉換、留存）
3. **假設**：是什麼造成表現不佳？（受眾、訊息、創意、優惠、時機、技術）
4. **排序**：哪些修正能以最少的努力產生最大的影響？
5. **測試**：設計實驗來驗證假設
6. **衡量**：這個改動有改善指標嗎？
7. **擴大或迭代**：有效的廣泛推行；沒定論或失敗的測試就迭代

### 依漏斗階段的優化槓桿

| 漏斗階段 | 問題訊號 | 優化槓桿 |
|-------------|---------------|---------------------|
| 知名度（Awareness） | 低曝光、低觸及 | 預算、目標對象、通路組合、創意形式 |
| 興趣（Interest） | 低 CTR、低互動 | 廣告創意、標題、內容鉤子、受眾定位 |
| 考慮（Consideration） | 高跳出率、低頁面停留時間 | 登陸頁內容、頁面速度、內容相關性、UX |
| 轉換（Conversion） | 低轉換率 | 優惠、CTA、表單長度、信任訊號、頁面版面 |
| 留存（Retention） | 高流失、低重複互動 | 引導、email 培養、產品體驗、客服支援 |

### 測試的最佳實務
- 一次只測一個變數，結果才乾淨
- 在啟動測試之前先定義成功指標
- 開始之前先算好需要的樣本數（不要提早結束測試）
- 測試至少跑滿一個完整的商業週期（B2B 通常是一週）
- 無論結果如何，都要記錄所有測試和結果
- 在團隊內分享學到的事，失敗的測試是有價值的資訊
- 確認現狀的測試不算失敗，它會增加你對目前做法的信心

### 持續優化的節奏
- **每天**：監控付費活動的預算進度、異常和被拒的廣告
- **每週**：檢視通路成效，暫停表現差的，擴大表現好的
- **每兩週**：更新廣告創意並測試新的變體
- **每月**：完整的成效檢視，找出新的優化機會，更新預測
- **每季**：策略性檢視通路組合、預算分配和目標對象策略

## 輸出格式

- 資料用表格呈現
- 關鍵數字和趨勢用粗體
- 主管摘要要精簡（適合轉寄給管理層）
- 如果使用者提供了大量指標，加入一個「詳細附錄」區段放細部資料

- Draft a stakeholder email with the key takeaways?
- Dive deeper into any specific metric or channel?
- Set up a reporting template you can reuse next period?」
