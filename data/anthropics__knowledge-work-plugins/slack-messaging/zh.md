# Slack 訊息撰寫最佳實務

這個 skill 提供撰寫格式正確、有效的 Slack 訊息的指引。

## 何時使用

只要是撰寫、起草或協助使用者寫 Slack 訊息，就套用這個 skill，包括使用 `slack_send_message`、`slack_send_message_draft` 或 `slack_create_canvas` 的時候。

## Slack 格式（mrkdwn）

Slack 用自己的標記語法，叫 **mrkdwn**，跟標準 Markdown 不一樣。寫 Slack 訊息一律用 mrkdwn：

| Format | Syntax | Notes |
|--------|--------|-------|
| 粗體 | `*text*` | 單個星號，不是兩個 |
| 斜體 | `_text_` | 底線 |
| 刪除線 | `~text~` | 波浪號 |
| 行內程式碼 | `` `code` `` | 反引號 |
| 程式碼區塊 | `` ```code``` `` | 三個反引號 |
| 引用 | `> text` | 角括號 |
| 連結 | `<url\|display text>` | 角括號內用直線分隔 |
| 提及使用者 | `<@U123456>` | 角括號內放使用者 ID |
| 提及頻道 | `<#C123456>` | 角括號內放頻道 ID |
| 項目符號清單 | `- item` 或 `• item` | 破折號或圓點字元 |
| 編號清單 | `1. item` | 數字加句點 |

### 常見錯誤，要避免

- 絕對不要用 `**bold**`（兩個星號），Slack 用的是 `*bold*`（單個星號）
- 絕對不要用 `## headers`，Slack 不支援 Markdown 標題。改成獨立一行的 `*bold text*`。
- 絕對不要用 `[text](url)` 寫連結，Slack 用 `<url|text>` 格式
- 絕對不要用 `---` 當分隔線，Slack 不會渲染

## 訊息結構指引

- **先講重點。** 最重要的資訊放第一行。很多人用手機或看通知，只看得到第一行。
- **保持簡短。** 目標是 1-3 個短段落。訊息太長就考慮改用 Canvas。
- **多換行。** 一大坨文字很難讀。不同的想法用空行隔開。
- **清單用項目符號。** 超過 3 項的內容要列成清單，不要寫成一長串。
- **關鍵資訊加粗。** 人名、日期、期限和待辦事項用 `*bold*`，掃過去才抓得到。

## 討論串與頻道的禮儀

- 回應特定訊息時**在討論串回覆**，主頻道才會乾淨。
- 只有回覆內容是所有人都該看到時，才用 **`reply_broadcast`**（同時發到頻道）。
- 開新話題、發公告或對整個群組提問時，**發在頻道裡**（不要開討論串）。
- **不要另開新討論串**來延續既有的對話，去找原本那則訊息回覆。

## 語氣與對象

- 語氣要配合頻道，`#general` 通常比 `#random` 正式。
- 單純表示收到時，用表情符號回應代替回覆訊息（但注意：MCP 工具不能加反應，必要時建議使用者自己手動加）。
- 寫公告時用清楚的結構：背景、重點資訊、行動呼籲。
