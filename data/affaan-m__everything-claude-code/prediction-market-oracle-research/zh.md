# Prediction Market Oracle Research

當預測市場正被考慮當成資料來源、預測輸入、類 oracle 訊號，或決策情報層時，使用這個 skill。

## 護欄

- 不要把市場價格當成客觀真相。
- 不要提供投資建議或交易建議。
- 把交易場所的機制、流動性、誘因和結算規則，跟隱含的訊號分開。
- 要點出操縱、流動性薄弱、停滯的市場和模糊的結果。
- 對鏈上或和執行相連的系統，在授予任何寫入權限之前，先跑 `llm-trading-agent-security`。

## 研究流程

1. 定義這個訊號要輔助的決策。
2. 找出相關的市場、事件、標籤和交易場所。
3. 記錄市場隱含的機率，附上時間戳記和來源連結。
4. 評估訊號品質：
   - 流動性
   - 價差
   - 市場存續時間
   - 交易者/誘因的集中程度（如果知道的話）
   - 結算權威
   - 地理或帳號限制
5. 拿它跟非市場的來源比較，例如申報文件、新聞、民調、研究、客戶資料或內部 KPI。
6. 建議這個訊號對所述的決策而言，是可用、薄弱，還是不適用。

## 整合模式

- 研究助理：為人類分析師提供有來源依據的背景。
- 儀表板訊號：把市場隱含機率，跟內部指標並列。
- Agent 記憶輸入：一個有時間戳記、之後可以取回的訊號。
- 警示輸入：機率、價差或流動性越過門檻時發出通知。
- 情境規劃：比較多種事件結果，但不自動化交易。

## 輸出格式

使用：

1. 決策背景
2. 市場來源
3. 訊號品質
4. 比較用的來源
5. 整合建議
6. 注意事項

最後以這句收尾：

```text
Prediction-market signals are informational inputs, not investment advice.
```
