# Manim 影片

在動態、結構與清晰度比擬真更重要的技術解說上使用 Manim。

## 何時啟用

- 使用者想要技術解說動畫
- 概念是圖表、工作流程、架構、指標變化或系統圖
- 使用者想要給 X 或 landing page 的簡短產品或發表解說
- 視覺要有精準感，而不是千篇一律的電影感

## 工具需求

- `manim` CLI，用於場景 render
- `ffmpeg`，需要時用於後製
- `video-editing`，用於最後組裝或潤飾
- `remotion-video-creation`，當最終成品需要合成 UI、字幕或額外的動態圖層時使用

## 預設輸出

- 短的 16:9 MP4
- 一張縮圖或海報畫面
- 分鏡腳本加場景規劃

## 工作流程

1. 用一句話定義核心的視覺論點。
2. 把概念拆成 3 到 6 個場景。
3. 決定每個場景要證明什麼。
4. 在寫 Manim 程式碼之前，先寫場景大綱。
5. 先 render 最小可運作的版本。
6. render 能跑之後，再調整字體排印、間距、色彩與節奏。
7. 只有在有加分時，才交給更完整的影片工具鏈。

## 場景規劃規則

- 每個場景只證明一件事
- 避免塞得過滿的圖
- 優先逐步揭露，而不是整個畫面一次塞滿
- 用動態來解釋狀態變化，而不是只為了讓畫面不空
- 標題卡要短，而且意義豐富

## 網路圖預設

針對社群圖譜與網路最佳化的解說：

- 先顯示目前的圖，再顯示最佳化後的圖
- 區分低訊號的追蹤雜訊與高訊號的橋接節點
- 突顯暖路徑節點與目標群集
- 有用的話，加一個最後的場景，呈現啟發這個 skill 的自我改進脈絡

## Render 慣例

- 預設用 16:9 橫式，除非使用者要求直式
- 先做低畫質的 smoke test render
- 構圖與節奏穩定之後，才拉高畫質
- 匯出一張乾淨、在社群尺寸下看得清楚的縮圖畫面

## 可重用的起手範本

把 [assets/network_graph_scene.py](assets/network_graph_scene.py) 當成網路圖解說的起點。

Smoke test 範例：

```bash
manim -ql assets/network_graph_scene.py NetworkGraphExplainer
```

## 輸出格式

回傳：

- 核心視覺論點
- 分鏡腳本
- 場景大綱
- render 計畫
- 任何後續潤飾的建議

## 相關 Skill

- `video-editing`：最後潤飾
- `remotion-video-creation`：動態密集的後製或合成
- `content-engine`：當動畫是更大的發表活動的一部分時
