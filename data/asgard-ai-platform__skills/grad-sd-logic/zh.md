# Service-Dominant Logic (S-D Logic)

## Overview

服務主導邏輯把行銷從以商品為中心（交換價值）重新框定為以服務為中心（使用價值）。Vargo 和 Lusch（2004、2008、2016）提出基礎前提：服務是交換的根本基礎，價值永遠是和受益者共同創造的，所有經濟行為者都是資源整合者。

## When to Use

- 重新設計價值主張，強調服務和成果
- 分析價值如何在行為者網絡中共創
- 把組織的心態從以產品為中心，轉向以服務為中心
- 設計服務生態系和平台策略

## When NOT to Use

- 既有製造流程的營運成本最佳化
- 需要商品主導會計方式的短期定價決策
- 利害關係人要求傳統財務指標，而且不接受轉換

## Assumptions

```
IRON LAW: Value is ALWAYS co-created. The firm can only offer value
propositions, not deliver value. Value is uniquely and phenomeno-
logically determined by the beneficiary in context of use.
```

關鍵假設：
1. 服務（能力的應用）是交換的根本基礎
2. 商品是提供服務的配送機制
3. 操作性資源（知識、技能）是優勢的主要來源
4. 所有行為者（企業、客戶、夥伴）都是資源整合者
5. 價值永遠是在服務生態系內共創的

## Methodology

### Step 1 — Map the foundational premises

透過 S-D Logic 的關鍵基礎前提（FP）來評估現有的事業：

| FP | Premise | Diagnostic Question |
|----|---------|-------------------|
| FP1 | 服務是交換的根本基礎 | 我們的產品讓人得以應用什麼能力？ |
| FP6 | 價值由多個行為者共創 | 除了企業之外，誰還參與了價值創造？ |
| FP7 | 行為者無法交付價值，只能提出主張 | 我們是否假設價值是內建在產品裡的？ |
| FP9 | 所有行為者都是資源整合者 | 客戶在交換中帶來了什麼資源？ |
| FP10 | 價值由受益者獨特地決定 | 我們衡量的是使用價值，還是只有交換價值？ |

### Step 2 — Identify operant vs operand resources

| Resource Type | Definition | Examples |
|--------------|-----------|----------|
| **Operand** | 被作用的資源（靜態） | 原物料、設備、金錢 |
| **Operant** | 作用於其他資源的資源（動態） | 知識、技能、技術、關係 |

把策略重心從操作對象資源（operand）轉向操作性資源（operant）。

### Step 3 — Map the service ecosystem

找出價值共創網絡中所有的行為者、制度和資源流動：
- 微觀層級：雙方互動（企業與客戶）
- 中觀層級：服務系統和平台
- 宏觀層級：制度安排和共同規範

### Step 4 — Redesign value propositions

把產品重新框定為能促成受益者創造價值的價值主張：
- 從「我們賣什麼」到「我們促成什麼成果」
- 從「產品功能」到「資源整合的支援」
- 從「交付」到「促進共創」

## Gotchas

- S-D Logic 是一種視角或心態，不是預測模型，它重新框定思考，但不預測結果
- 「共創」不代表客戶要做事，而是代表價值是在使用情境中浮現的
- 當資源整合失敗時，可能發生價值共毀，不要假設共創永遠是正面的
- 操作性資源比操作對象資源更難衡量，不要預設回到有形的指標
- S-D Logic 的詞彙（operant/operand、服務生態系）可能讓實務工作者感到疏離，翻譯時要小心
- 制度與制度邏輯（2016 年更新時加入）對生態系層級的分析至關重要
