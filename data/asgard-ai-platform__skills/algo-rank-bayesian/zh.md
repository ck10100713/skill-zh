# 貝氏平均評分（Bayesian Average Rating）

## 概述

貝氏平均把項目觀察到的平均評分，和先驗（全域平均）結合起來，用評論數當權重。公式：BR = (C × m + Σrᵢ) / (C + n)，其中 m=全域平均、C=信心參數、n=該項目的評論數、Σrᵢ=該項目評分的總和。評論少的項目會被拉向全域平均。

## 何時使用

**觸發條件：**
- 要用連續評分（1-5 顆星）替評論數不一的項目排名
- IMDB 風格的「Top 250」榜單，要在品質和人氣之間取得平衡
- 任何評分彙總的情境，不想讓只有少數高分的新項目霸榜

**何時不要用：**
- 二元（讚／倒讚）資料（改用 Wilson Score）
- 所有項目的評論數都差不多時（簡單平均就夠了）

## 演算法

```
鐵律：先驗能防止小樣本的極端值
沒有先驗的話，一則 5 星評論就能讓項目變成「最棒的」。
貝氏平均會在全域平均 m 的位置加上 C 張「幽靈票」，
把小樣本的項目往平均值收縮。C 控制收縮的力道：
C 越高 = 越保守（幽靈票越多）。
典型的 C = 所有項目評論數的中位數。
```

### 階段 1：輸入驗證
計算：所有項目的全域平均評分（m）、選定 C（幽靈票數）。每個項目要蒐集：評論數（n）、平均評分或評分總和。
**關卡：** m 已算出、C 已選定、項目資料齊全。

### 階段 2：核心演算法
1. 全域平均：m = Σ(所有評分) / Σ(所有評論數)
2. 每個項目的貝氏平均：BR = (C × m + n × avg_rating) / (C + n)
3. 依 BR 由高到低排名
4. n >> C 的項目，BR ≈ avg_rating（資料主導）。n << C 的項目，BR ≈ m（先驗主導）。

### 階段 3：驗證
檢查：評論很少的項目應該接近全域平均。評論很多的項目應該接近它們實際的平均。排名要符合直覺。
**關卡：** 已確認收縮行為，榜首項目同時具備高評分「和」足夠的評論數。

### 階段 4：輸出
回傳依貝氏分數排好的項目。

## 輸出格式

```json
{
  "rankings": [{"item": "Movie_A", "bayesian_avg": 8.7, "raw_avg": 9.1, "reviews": 5000, "shrinkage": 0.04}],
  "metadata": {"global_mean": 6.8, "confidence_C": 500, "items_ranked": 10000}
}
```

## 範例

### 輸入輸出範例
**輸入：** m=7.0, C=100。項目 A：avg=9.5, n=5。項目 B：avg=8.5, n=500。
**預期：** BR_A = (100×7 + 5×9.5)/(105) = 7.12。BR_B = (100×7 + 500×8.5)/(600) = 8.25。B 排名較高。

### 邊界情況
| 輸入 | 預期 | 原因 |
|-------|----------|-----|
| n=0 | BR = m（全域平均） | 沒有資料，完全由先驗決定 |
| n=100000 | BR ≈ 原始平均 | 龐大的樣本壓過先驗 |
| 所有項目的 n 相同 | 等同於簡單平均排名 | 收縮是一致的，排序不變 |

## 常見陷阱

- **C 的選擇是主觀的**：常見選法：評論數的中位數、讓評分算「可靠」的最低評論數（IMDB 用的是投票數前 25,000 名的投票者，並設有最低票數）。沒有放諸四海皆準的值。
- **評分尺度很重要**：5 分制的 4.0 和 10 分制的 4.0 意思不同。要正規化，或使用同一個尺度。
- **各類別專屬的先驗**：「恐怖片」的平均 4.0 可能很出色，但「吉卜力」的 4.0 可能低於平均。可以考慮用類別層級的先驗。
- **時間偏誤**：老項目會累積評論。除非你對近期評論加重權重，否則老牌項目會永遠霸佔「top」榜單。
- **刷評論**：貝氏平均擋不住操弄評論，它只能緩解小樣本的極端值。要搭配詐欺偵測。
