# 需求價格彈性（Price Elasticity of Demand）

## 概述

價格彈性衡量價格每變動 1%，需求量變動的百分比。Ed = %ΔQ / %ΔP。|Ed| > 1 = 有彈性（對價格敏感），|Ed| < 1 = 缺乏彈性（對價格不敏感）。對定價決策和營收最佳化至關重要。

## 何時使用

**觸發條件：**
- 要估算調價會如何影響銷售量和營收
- 要判斷某個產品的需求有彈性還是缺乏彈性
- 要把價格最佳化到營收或利潤最大

**何時不要用：**
- 需要的是消費者願付價格的分布時（用 Van Westendorp 或聯合分析）
- 多個產品要一起定價時（用組合包定價）

## 演算法

```
鐵律：在線性需求曲線上，彈性不是常數。每個價格點都不一樣。價格高時需求有彈性（小幅漲價 → 銷量大跌），價格低時需求缺乏彈性。一定要在你關心的「特定價格點」上計算。讓營收最大的價格，就是 Ed = -1（單位彈性）的地方。
```

### 階段 1：輸入驗證
蒐集：隨時間（或跨市場）的價格與數量配對。要控制：季節性、促銷、競爭者動作、其他混淆因子。
**關卡：** 至少 10 筆價格與數量的觀測值、混淆因子已辨識。

### 階段 2：核心演算法
**點彈性：** 在特定價格點上，Ed = (dQ/dP) × (P/Q)
**弧彈性：** 兩點之間，Ed = ((Q₂-Q₁)/((Q₂+Q₁)/2)) / ((P₂-P₁)/((P₂+P₁)/2))
**迴歸法：** log(Q) = α + β×log(P) + controls → β 就是彈性（固定彈性模型）

### 階段 3：驗證
檢查：符號應該是負的（價格上升 → 數量下降）。用 holdout 期間做交叉驗證。
**關卡：** 彈性為負、信賴區間合理。

### 階段 4：輸出
回傳彈性估計，並附上營收影響的推估。

## 輸出格式

```json
{
  "elasticity": -1.5,
  "interpretation": "elastic — 1% price increase → 1.5% quantity decrease",
  "revenue_impact": {"price_change_pct": 10, "quantity_change_pct": -15, "revenue_change_pct": -6.5},
  "metadata": {"method": "log-log regression", "r_squared": 0.82, "observations": 52}
}
```

## 範例

### 輸入輸出範例
**輸入：** 價格從 $100 漲 10% 到 $110，數量從 1000 掉到 850
**預期：** 弧彈性 = ((-150/925) / (10/105)) = -1.70（有彈性）

### 邊界情況
| 輸入 | 預期 | 原因 |
|-------|----------|-----|
| 奢侈品 | 可能是正的（Veblen 效應） | 價格越高 → 感知價值越高 |
| 必需品（胰島素） | 接近零 | 需求幾乎不隨價格變動 |
| 有完全替代品 | 非常有彈性（< -3） | 顧客馬上轉換 |

## 常見陷阱

- **遺漏變數偏誤**：沒控制廣告、季節性和競爭者價格的話，彈性估計會有偏誤。
- **短期 vs 長期**：短期彈性通常比較低（顧客被綁住）。長期則給了他們時間去找替代品。
- **交叉價格彈性**：產品 A 的需求可能取決於產品 B 的價格。在產品組合的情境下忽略這點，會讓定價不是最佳。
- **不對稱彈性**：消費者對漲價和降價的反應可能不同。別假設對稱。
- **小樣本雜訊**：觀測值少的時候，彈性估計的信賴區間會很寬。要報區間，不要只報點估計。
