# 動態定價（Dynamic Pricing）

## 概述

動態定價會依需求訊號、時間、庫存和競爭狀況即時調整價格。常見於航空、飯店、叫車和電商。目標：在產能／庫存限制下，讓營收（或利潤）最大化。

## 何時使用

**觸發條件：**
- 要替易逝性庫存定價（飯店房間、機位、活動票券）
- 要替電商實作隨需求變動的定價
- 要建立 surge 定價或依時段定價的系統

**何時不要用：**
- 一次性的定價決策（用 Van Westendorp 或聯合分析）
- 價格調整不切實際時（受管制的市場、長期合約）

## 演算法

```
鐵律：動態定價需要即時資料。過期的資料算出來的是「過去」最佳的價格，不是現在的。三個資料流都必須是最新的：1. 需求訊號（訂位、搜尋、加入購物車）2. 庫存／產能狀態 3. 競爭者價格（適用時）。更新頻率：叫車是分鐘級，飯店是小時級，零售是每天。
```

### 階段 1：輸入驗證
蒐集：目前的需求指標、剩餘庫存／產能、距離到期／活動的時間、競爭者價格、價格下限／上限的限制。
**關卡：** 即時資料串流已接上、商業規則已定義。

### 階段 2：核心演算法
**規則式：** 需求 > 門檻就加價 X%。依庫存水位設定分層規則。

**需求曲線式：** 1. 估計目前條件下的需求曲線。2. 找出讓營收 = P × Q(P) 最大的價格。3. 套用庫存限制：產能吃緊就漲價，有多餘就降價。

**機器學習式：** 訓練模型，在給定情境特徵下預測每個價格點的需求。在預測出的需求曲線上做最佳化。

### 階段 3：驗證
監控：單位營收、訂位速度、客訴、競爭地位。新的定價規則要做 A/B 測試。
**關卡：** 營收有提升，且沒有明顯的銷量流失或客戶反彈。

### 階段 4：輸出
回傳建議價格，附上理由和預期影響。

## 輸出格式

```json
{
  "recommended_price": 1200,
  "current_price": 999,
  "reasoning": {"demand_signal": "high", "inventory_remaining_pct": 15, "competitor_avg": 1100},
  "expected_impact": {"revenue_change_pct": 18, "volume_change_pct": -5},
  "metadata": {"strategy": "demand-curve", "update_frequency": "hourly"}
}
```

## 範例

### 輸入輸出範例
**輸入：** 飯店房間，距離入住日 3 天，住房率 85%，競爭者平均價格 $150
**預期：** 價格高於競爭者（$160-170），因為住房率高、時間視窗短。

### 邊界情況
| 輸入 | 預期 | 原因 |
|-------|----------|-----|
| 零需求 | 降到價格下限 | 刺激需求，至少回收一些營收 |
| 剩最後一個 | 價格接近上限 | 稀缺性會讓願付價格最大化 |
| 競爭者閃購 | 沒必要就不要自動跟進 | 避免價格戰；先評估你的產品有沒有差異化 |

## 常見陷阱

- **顧客的公平感**：看得見的價格歧視（同一個產品，不同使用者價格不同）會引發反彈。要依時間、通路或組合包來區分，不要依個人。
- **價格戰螺旋**：自動化的競爭定價可能造成逐底競爭。要設絕對下限和變動速率上限。
- **需求自我蠶食**：顧客發現價格之後會降，就會等。這是「策略性顧客」問題，別訓練顧客延後購買。
- **法規風險**：動態定價在緊急時期可能違反反哄抬物價的法律。要內建法律限制規則。
- **A/B 測試偏誤**：測試不同價格會讓營收衡量變困難。控制組放在「錯的」價格，本來就注定虧錢。
